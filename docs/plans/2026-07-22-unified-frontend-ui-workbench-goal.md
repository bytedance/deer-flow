# DeerFlow 统一前端 UI 工作台目标

> 目标类型：前端整体 UI / 交互重构规划
>
> 关联 issue：[bytedance/deer-flow#4362](https://github.com/bytedance/deer-flow/issues/4362)
>
> 创建日期：2026-07-22
>
> 状态：待人工设置目标，尚未开始大规模实现

## 1. 总目标

围绕 issue #4362，为 DeerFlow 建立一套统一、美观、实用的前端组件和页面排版系统。范围不局限于首页或配色，而是覆盖所有用户能够看见的页面、菜单、弹窗、抽屉、面板和状态。

最终产品方向：

> 将 DeerFlow 统一重构为适合高频编码、自动化和智能体工作流的 AI Harness 工作台（Harness Workbench）。

重点是清晰的层级、稳定的操作位置、适合长时间使用的信息密度，以及桌面端和移动端都一致的交互逻辑。不要把它做成营销页，也不要再创建一套独立的“皮肤系统”。

## 2. 当前基础与必须保留的内容

当前工作区已经存在以下修改，后续实现必须在其基础上工作，不得擅自覆盖：

- `frontend/src/styles/globals.css` 中的 Tiesen 语义配色。
- `frontend/src/app/workspace/scheduled-tasks/page.tsx` 中的状态筛选和类型筛选下拉框。
- `frontend/tests/e2e/scheduled-tasks.spec.ts` 对筛选下拉框的测试更新。
- 根目录、`backend/`、`frontend/` 下 `AGENTS.md` 的既有修改。

以下内容已经被用户明确认为不适合 Harness，不得恢复：

- Command Center / 指挥中心布局。
- Tiesen 专属独立布局。
- `data-skin` 皮肤机制。
- 皮肤选择器。
- `theme-lab` 实验路由。
- 专属皮肤截图和 E2E 测试。

配色可以继续保留，但不能重新引入独立皮肤切换系统或另一套页面骨架。

## 3. 设计目标

### 3.1 统一

- 所有工作区页面使用同一套页面容器、标题栏、工具栏、列表行、详情面板和状态反馈。
- 页面标题、说明、当前状态和主要操作有固定位置。
- 按钮、图标按钮、菜单、弹窗、抽屉和空状态遵循统一规范。
- 设置、Command Palette、侧栏和页面内菜单使用一致的命名和操作层级。

### 3.2 简洁

- 常用操作直接显示，低频操作收进“更多”菜单。
- 删除、重置等危险操作只在明确的危险操作区出现。
- 不重复显示相同的“对话 / 智能体 / 定时任务”入口。
- 避免无意义的卡片套卡片和过多边框。
- 内容优先，装饰从属于工作流。

### 3.3 对称和居中

- 主内容在侧栏剩余空间中使用统一最大宽度并居中。
- 页面不会因为删除左侧导航而整体偏到屏幕右侧。
- 标题栏、筛选区、列表和详情面板使用同一内容轴线。
- 对话消息和输入框保留适合阅读与输入的最大宽度。

### 3.4 工作流优先

- 新建对话是全局唯一的高优先级主操作。
- 用户可以从侧栏、页面标题栏和欢迎页完成核心导航，但不会看到重复的同一组按钮。
- 对话、智能体和定时任务的列表、详情、编辑流程采用相同的布局思维。
- 保持现有后端 API、线程生命周期、流式输出、上传、Artifacts、Sidecar、技能和任务执行逻辑不变。

### 3.5 响应式和可访问性

- 桌面端使用侧栏和多栏工作台布局。
- 移动端明确使用抽屉、单栏列表到详情导航，不只是把桌面布局压缩。
- 图标按钮有可访问名称和 tooltip。
- 键盘可以完成导航、搜索、菜单、弹窗和主要提交操作。
- 所有页面考虑加载、空数据、错误、禁用、权限不足和网络不可用状态。

## 4. 统一页面骨架

桌面端目标结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ DeerFlow        全局搜索 / Cmd+K       页面操作       设置   │
├────────────────┬─────────────────────────────────────────────┤
│ [+ 新建对话]   │ 页面标题                         主要操作   │
│                │ 页面说明 / 状态 / 必要面包屑                │
│ 工作区         ├─────────────────────────────────────────────┤
│  对话          │ 搜索 / 筛选 / 排序 / 视图工具栏             │
│  智能体        ├─────────────────────────────────────────────┤
│  定时任务      │                                             │
│                │                    页面内容                 │
│ 资源           │                                             │
│  频道          │                                             │
│                │                                             │
│ 最近对话       │                                             │
│                │                                             │
│ 设置           │                                             │
└────────────────┴─────────────────────────────────────────────┘
```

统一规则：

- 左侧保留标准 DeerFlow 侧栏，但重新分组和整理层级。
- 侧栏收起时保留图标、当前状态和 tooltip；展开时显示分组标题。
- 一级页面直接显示页面标题，不用冗余的 `Workspace / Chats` 路径代替标题。
- 面包屑只用于深层页面，例如“智能体 / 某个智能体 / 对话”。
- 页面操作集中在标题栏右侧。
- 筛选、搜索、排序和视图密度集中在标题栏下方的工具栏。
- 页面主内容在可用区域内居中，使用稳定的最大宽度。
- 不同页面不得各自发明不同的标题字号、边距、圆角和边框层级。

## 5. 侧栏信息架构

目标结构：

```text
DeerFlow
[+ 新建对话]

工作区
  对话
  智能体
  定时任务

资源
  频道

最近对话
  对话一
  对话二
  对话三

底部
  设置
  帮助 / GitHub
```

行为要求：

- “新建对话”是侧栏唯一的高强调主按钮。
- “对话、智能体、定时任务”只保留一组主导航入口。
- 最近对话是独立的可滚动区域，不与主导航混在一个层级。
- 频道属于资源区，不与页面导航处于相同视觉层级。
- 设置、帮助、GitHub 等低频入口集中在底部或统一菜单。
- 智能体功能不可用时，继续保留清晰的禁用状态和原因提示。

## 6. 首页 / 新对话排版

首页应成为真正的工作入口，而不是重复导航按钮集合：

```text
                  DeerFlow
          你今天想完成什么？

              [ 对话输入框 ]

        对话       智能体       定时任务
        最近对话 / 最近使用智能体 / 任务状态
```

行为：

- 欢迎状态下显示“对话 / 智能体 / 定时任务”三个快捷入口。
- 三个快捷入口在首页出现时，其他位置不再显示同一组重复入口。
- 用户开始输入、提交消息、向下滚动或离开欢迎状态后，快捷入口隐藏。
- 页面滚动后顶部出现精简固定工具栏，接管当前页面和必要操作。
- 快捷入口使用统一的图标和紧凑入口样式，不做巨大的营销卡片。
- 保留现有输入框的模型、附件、模式、目标、待办和技能能力。

验收重点：

- 欢迎状态同一功能不会同时出现在三个地方。
- 开始对话后页面顶部不出现多余的首页按钮。
- 桌面端输入区和快捷入口在视觉中心对齐。
- 移动端没有横向溢出，快捷入口可自然换行或变成紧凑列表。

## 7. 对话列表页

目标结构：

```text
对话                                      [新建对话]
管理全部对话
[搜索] [来源筛选] [时间排序] [列表密度]

今天
  对话标题       来源       更新时间       更多
昨天
  对话标题       来源       更新时间       更多
```

改造内容：

- 统一使用 `WorkspacePageHeader` 和 `WorkspaceToolbar`。
- 搜索、来源筛选、时间排序、列表密度放在同一工具栏。
- 每一行使用统一的 `WorkspaceListRow`。
- 列表行展示标题、来源、更新时间和必要状态。
- 重命名、分享、导出、删除统一收进每行的更多菜单。
- 增加加载状态、空状态、错误状态和搜索无结果状态。
- 保留当前无限分页、搜索时显式加载更多和后端线程 API。
- 移动端隐藏次要字段，更多菜单固定在行尾。

## 8. 对话详情页

目标结构：

```text
顶部线程栏
[返回 / 侧栏] 线程标题   状态       定时任务   更多

消息区
  用户消息
  智能体消息
  工具调用 / 文件 / 计划 / 目标 / 待办

输入区
  附件   模式   模型                         发送
```

桌面端：

- 中间消息区域保持适合阅读的最大宽度。
- Artifacts、Sidecar、引用和变更使用统一右侧面板。
- 右侧面板统一标题、关闭按钮、空状态、加载状态和滚动行为。
- 顶部不同时暴露过多按钮；导出、分支、删除等低频操作进入更多菜单。
- 工具调用、计划、目标和待办统一为可折叠的内联区块。
- 保持流式消息、重新生成、分支、人工输入和停止运行行为。

移动端：

- 顶部只显示线程标题和一个更多按钮，必要时保留侧栏触发器。
- Artifacts、Sidecar、引用和变更全部使用右侧抽屉。
- 输入区按“附件 / 模式 / 模型 / 发送”分层，避免按钮拥挤。
- 确保输入框、消息内容和抽屉不会相互遮挡。

## 9. 智能体页面

### 9.1 智能体列表

不要继续把页面当成单纯展示用的卡片墙，改成资源管理页：

```text
智能体                                      [新建智能体]
管理你的专用工作流
[搜索] [标签 / 状态筛选]

┌──────────────┬────────────────────────────┐
│ 智能体列表    │ 选中智能体详情              │
│ Researcher   │ 名称 / 描述 / 最近使用       │
│ Coder        │ [开始对话] [更多]            │
│ Writer       │ 最近对话                     │
└──────────────┴────────────────────────────┘
```

- 桌面端使用 master-detail 布局。
- 移动端使用列表到详情的单栏导航。
- 支持搜索、标签或状态筛选、最近使用信息和清晰的空状态。
- 常用操作显示“开始对话”，删除等危险操作收进更多菜单。
- 不改变现有智能体 API、功能开关和删除确认流程。

### 9.2 新建智能体

- 第一步只负责输入和校验名称。
- 第二步进入与普通对话一致的创建工作区。
- 返回、保存、取消和更多操作统一放入标题栏。
- 创建成功后显示统一成功状态和下一步操作。
- 保留名称检查、引导消息、保存智能体、人工输入和重试逻辑。
- 不让创建页和普通对话页各自维护完全不同的顶部结构。

## 10. 定时任务页面

目标结构：

```text
定时任务                                  [新建任务]
管理自动运行的工作流
[状态筛选] [类型筛选] [排序]

任务列表                         任务详情
每日研究报告                     状态：运行中
每周总结                         下次运行
                                 上次运行
                                 最近运行记录
                                 [暂停] [立即运行] [更多]
```

改造内容：

- 默认优先显示任务列表，避免创建表单占据首屏。
- 创建任务打开右侧抽屉或专注式编辑面板。
- 保留现有状态筛选和类型筛选下拉框，只调整位置和视觉层级。
- 配方模板改成紧凑选择器或模板入口。
- “新线程 / 复用线程”改成明确的分段控制。
- 任务详情用状态摘要、下一次运行、上次运行和运行时间线组织信息。
- 暂停、恢复、立即运行是常用操作；编辑和删除放入更多菜单。
- 删除继续使用危险操作确认弹窗。
- 移动端采用“任务列表 -> 任务详情 -> 编辑”的单栏模式。
- 不改变定时任务 API、任务状态语义、运行生命周期和线程复用行为。

## 11. 设置、菜单和弹窗

### 11.1 设置

当前设置已经有侧栏和内容区，但需要进一步统一为工作台式设置面板。

建议分组：

- 账户
- 外观
- 通知
- 工作区资源：频道、记忆、工具、技能
- 关于

统一规则：

- 设置弹窗宽度、标题栏、左侧导航和滚动区域固定规范。
- 所有设置 section 使用统一标题、描述、字段间距和保存反馈。
- 长内容只在内容区滚动，避免整个弹窗跳动。
- 移动端左侧设置导航变成顶部选择器或抽屉。
- 频道配置、技能创建和记忆管理使用统一的表单、状态和确认反馈。

### 11.2 菜单和弹窗

- 全局更多菜单统一宽度、图标、分隔线和危险操作颜色。
- Command Palette 的名称必须和侧栏、页面标题、菜单名称一致。
- 重命名、删除、导出、分享、暂停、恢复等操作采用统一菜单结构。
- 所有图标按钮提供 tooltip 和无障碍名称。
- 确认弹窗统一标题、描述、取消按钮和危险确认按钮的位置。
- 弹窗内容较长时使用明确的内部滚动区，不让按钮离开可视区域。
- 低频按钮不在多个位置重复出现。

## 12. 公共页面

登录、初始化设置、Landing、Docs、Blog 可以保留各自的内容属性，但共享基础视觉规范：

- DeerFlow 品牌头部和导航。
- 字体、颜色、间距和按钮语义。
- 输入框、状态提示、加载状态和错误提示。
- 明暗主题变量。
- 移动端导航行为。
- 页脚、GitHub、文档和外部链接样式。

认证页面目前与工作台的视觉语言差异较大，后续建议：

- 减少过重的装饰背景。
- 使用克制的居中认证布局或清晰的双栏布局。
- 登录和初始化设置共用表单容器、标题、错误状态和提交按钮规范。
- 不改变认证 API、重定向安全校验、SSO、初始化管理员和修改密码行为。

Landing、Docs、Blog 不强行套用工作区侧栏，只统一品牌、导航和基础组件。

## 13. 推荐的 workspace 级组件

优先在 `frontend/src/components/workspace/` 层组合现有 UI primitives，不随意修改生成的 `frontend/src/components/ui/` 基础组件。

候选组件：

- `WorkspacePageHeader`
- `WorkspaceToolbar`
- `WorkspaceSectionHeader`
- `WorkspaceListRow`
- `WorkspaceDetailPanel`
- `WorkspaceEmptyState`
- `WorkspaceStatusBadge`
- `WorkspaceActionMenu`
- `WorkspaceResponsiveDrawer`

抽象原则：

- 只有在多个页面真实重复时才抽象。
- 组件负责稳定的布局和视觉语义，不吞掉页面业务逻辑。
- 业务 API、查询、提交和状态机继续留在各自领域模块。
- 不为了“看起来统一”增加不必要的包装层。

## 14. 分阶段实施顺序

### Phase 0：审计与设计基线

范围：

- 核对 issue #4362 和参考图。
- 盘点全部用户可见路由、菜单、弹窗、抽屉和面板。
- 确定页面标题栏、侧栏分组、内容宽度、间距、圆角、层级和响应式规则。
- 建立共享组件清单和视觉验收基线。

完成标准：

- 所有主要页面都有明确的目标排版。
- 明确哪些入口合并、哪些按钮隐藏、哪些操作移动到更多菜单。
- 不涉及业务代码大规模修改。

### Phase 1：统一工作区外壳

范围：

- 侧栏分组和最近对话区域。
- 统一页面标题栏。
- 页面内容容器和居中规则。
- 顶部操作区。
- 移动端导航抽屉。
- Settings、Command Palette 和更多菜单入口。

验收标准：

- 对话、智能体、定时任务三页的标题栏、宽度和间距一致。
- 桌面端内容不会偏向屏幕右侧。
- 移动端没有重复导航和横向溢出。
- 侧栏展开、收起、刷新和路由切换正常。
- 不改变业务 API 和现有核心交互。

### Phase 2：统一对话工作流

范围：

- 对话列表。
- 对话详情顶部线程栏。
- 输入区控件层级。
- Artifacts、Sidecar、引用和 Changes 右侧面板。
- 欢迎页快捷入口的显隐行为。

验收标准：

- 欢迎状态下三个入口只出现一次。
- 开始对话或滚动后入口隐藏，顶部工具栏接管必要操作。
- 发送、上传、模型选择、模式选择、工具调用、导出、分支和停止运行不回归。
- 桌面端右侧面板和移动端抽屉都能正常打开、关闭和滚动。

### Phase 3：智能体和定时任务

范围：

- 智能体 master-detail。
- 智能体创建流程。
- 定时任务列表、详情和创建抽屉。
- 任务运行记录和危险操作。

验收标准：

- 智能体创建、保存、开始对话、删除和禁用状态正常。
- 任务创建、编辑、筛选、暂停、恢复、立即运行和删除正常。
- 运行记录和失败状态诚实可见。
- 桌面端和移动端流程都能完成。
- 后端 API 和任务执行生命周期不改变。

### Phase 4：设置和公共页面

范围：

- 设置各 section。
- 频道、记忆、工具、技能和关于页面。
- 登录和初始化设置。
- Landing、Docs、Blog 的共享导航和基础视觉规范。

验收标准：

- 用户可见页面没有明显的标题、按钮、弹窗和状态样式断裂。
- 加载、空数据、错误、禁用和权限状态统一。
