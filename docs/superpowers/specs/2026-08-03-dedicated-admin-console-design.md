# 独立多租户运营后台设计

## 目标

把现有的单页“运营后台”升级为独立管理控制台。管理员登录后仅进入该控制台；普通用户继续使用自己的聊天与设置工作区。控制台面向一个注册用户即一个租户的产品模型，覆盖用户、积分、计费、用量、订单、技能市场和操作审计。

## 范围与边界

- 路由保留为 `/workspace/admin`，但使用独立的 `AdminShell`，不复用普通用户的工作区侧栏、聊天容器或设置弹窗。
- 管理员不能进入普通用户聊天与个人配置路由；普通用户不能进入后台路由。
- 后台只读取或操作平台级数据。用户的聊天、记忆、工具、集成、私有技能和 MCP 配置仍严格以 `user_id` 隔离。
- 本期保留微信、支付宝的模拟支付成功流程；不接入会产生费用的真实支付服务。
- 不在后台展示平台 API Key 明文。后续有供应商配置页面时，密钥仅接受更新和显示脱敏状态。

## 信息架构

### 概览

首屏显示租户总数、活跃用户、可用积分总额、当日充值、当日积分消耗、模型调用失败数和低余额用户数。下方提供近期用量趋势、模型消耗分布及待处理风险提示。

### 租户与用户

用户表支持邮箱、状态、角色、余额、注册时间与最近活跃时间筛选。详情抽屉显示账户状态、积分余额、积分账本、充值订单、模型用量和管理员操作历史。管理员可调整积分、冻结或恢复账户；每项变更要求填写原因并写入审计记录。管理员账户不得被自己冻结。

### 计费与模型

模型清单只使用聊天页面已配置且可选择的模型。每个模型对应一条当前生效策略，包含输入、输出、缓存单价（分/百万 Token）、积分倍率与最大预占积分。编辑保存创建新版本而不是覆盖历史；对话启动时根据选择模型命中对应策略。

### 用量与账单

按租户、模型、时间范围和任务状态查询。每行显示任务、输入/输出 Token、预占积分、最终扣减积分、执行时间和状态。提供总计卡片与 CSV 导出入口；导出实现使用服务端分页查询，避免浏览器加载全量账单。

### 充值订单

显示模拟微信和支付宝订单，按创建时间、渠道、状态、积分数量筛选。普通用户从个人积分页发起充值；管理员仅查看订单和异常状态。为真实支付预留外部订单号、回调状态、退款状态字段，但不接入支付渠道。

### 技能市场

管理员可创建草稿、编辑、发布、下架和新建版本。发布前显示技能正文、描述、版本与安全扫描结果；发布后显示安装用户数。普通用户在个人“设置 → 技能市场”浏览并安装，安装副本归用户所有，不影响其他租户。

### 内容安全

新增“内容安全”模块，采用规则优先、人工复核的第一期方案。它审核用户输入和模型输出，但管理员不会默认查看全量聊天：检测器只生成脱敏风险事件；审核员需填写理由才能受控查看事件关联的少量上下文，所有查看与处置均写入审计日志。

风险事件包含风险类别、等级、命中规则版本、置信度、用户、线程、运行、消息方向、脱敏摘要、状态与处置记录。首期处置包括误判关闭、警示用户、限制任务、冻结账户和升级处理。自动检测不得直接冻结账户。

模型流式输出在后端发布 SSE 前经 `StreamingContentGuard` 检查。增量文本先进入短缓冲窗口（80 至 150 个字符）再转发；命中高风险时停止后续转发，取消当前运行，持久化安全占位消息并发出 `content_blocked` SSE 事件。前端收到事件后必须以固定的中性安全提示整体替换当前助手消息，而不是保留已显示片段。用户刷新或重新进入线程时也只能看到安全占位消息。

输入在发送给模型前命中拦截时，不创建模型调用、不扣积分；模型已开始生成后命中拦截时，按实际消耗 Token 结算，不自动退还积分。仅管理员可以在确认误判后以明确原因手动补偿。

### 审计日志

记录管理员身份、动作、目标、原因、变更前后摘要、请求时间和关联对象。首期覆盖积分调整、账号状态、模型价格和技能市场发布；所有后台写操作统一从这里写入记录。

## 页面与组件

`AdminShell` 由固定侧栏、顶栏、主内容区组成：

1. 侧栏：概览、租户与用户、计费与模型、用量账单、充值订单、技能市场、内容安全、审计日志。
2. 顶栏：当前页面标题、全局搜索（首期搜索租户/订单）、管理员菜单。
3. 主区：指标卡、筛选栏、数据表格和详情抽屉；危险操作使用确认对话框，禁止浏览器 `prompt`。

页面按路由拆分，避免继续把数据请求和表单逻辑堆叠在 `admin/page.tsx` 中：

- `/workspace/admin`：概览
- `/workspace/admin/tenants`
- `/workspace/admin/billing`
- `/workspace/admin/usage`
- `/workspace/admin/orders`
- `/workspace/admin/skills`
- `/workspace/admin/safety`
- `/workspace/admin/audit`

## API 与数据规则

- 现有 `/api/admin/users`、`/api/admin/usage`、`/api/admin/model-pricing` 和 `/api/admin/skill-market` 改为支持分页、筛选和稳定排序的后台资源接口。
- 账户、余额、账本、用量和订单详情只向管理员开放；所有管理员写接口验证角色、CSRF、目标存在性和操作原因。
- 每个后台写接口生成审计事件。冻结操作额外拒绝冻结当前操作者，防止管理员锁死自己。
- 技能列表接口维持轻量简介；新增受访问者所属租户约束的技能详情读取接口，按需返回该技能的完整 `SKILL.md` 正文。前端详情面板以纯文本/Markdown 预览呈现，不执行正文中的脚本。
- 内容安全接口以风险事件为中心，不提供任意线程全文查询。审核员读取关联上下文时必须提供处理理由，服务端限制消息数量、执行脱敏并写入读取审计事件。
- 流式安全拦截在运行器发布 `messages` SSE 事件前完成；命中后持久化 `blocked` 终态与安全占位内容，并通过专用 SSE 事件让客户端替换已渲染的内容。

## 错误体验

- 401 跳转登录；403 显示无权限并重定向至角色对应首页。
- 余额不足保留目前友好积分提示，不把原始 HTTP 402 JSON 直接抛到界面。
- 保存失败在对应表单内呈现可理解原因，并保留用户输入。
- 空列表、加载中、无搜索结果分别有独立状态；后台数据请求失败提供重试。

## 验收与测试

- 路由测试：管理员可访问全部后台页面，普通用户和未登录用户无法访问。
- API 测试：分页/筛选、管理员权限、积分调整、冻结保护、模型策略版本、审计写入与风险事件受控查看。
- 前端测试：侧栏路由、筛选状态、确认对话框、技能详情按需加载与完整正文展示。
- 流式测试：安全内容正常逐步显示；命中输出规则后不再输出后续片段、已显示内容被替换、刷新后仍是安全占位；输入预拦截不扣费，输出拦截按实际 Token 结算。
- 回归：普通用户的聊天、记忆、工具、集成、技能和 MCP 设置保持租户隔离；现有积分预占/结算测试继续通过。

## 交付顺序

1. 独立后台壳层、路由与概览；
2. 租户用户、积分账本、用量与订单；
3. 模型计费、技能市场与审计；
4. 内容安全审核、流式拦截与安全占位消息；
5. 将技能“展开说明”改为按需展示完整 `SKILL.md`，并完成端到端回归。
