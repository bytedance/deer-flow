# 模型定价与积分指示设计

## 目标

运营后台的模型定价必须与对话输入框可选择的已配置模型保持一致；右上角原有的 Token 用量指示改为当前登录用户的可用积分。

## 模型策略

- 前端从现有 `/api/models` 读取模型列表，运营后台只允许从该列表选择模型，不能输入任意名称。
- 每个模型对应一套当前生效的策略：输入、输出和缓存 Token 的单价，积分倍率，以及启动任务时的预占额度。
- 不同模型可有不同策略；同一模型对所有用户定价一致，不按用户、套餐或时间段分流。
- 更新一个模型的策略时，旧策略保留为历史版本并失效，新任务只能读取该模型最新的生效策略。
- 已结算用量记录继续保存完整策略快照，因此改价不会影响历史账单。

## 交互

- 运营后台的策略表单使用模型下拉框，标签使用模型显示名，提交值使用模型唯一名称。
- 当前策略列表按模型显示，同时允许查看该模型已失效的历史版本。
- 聊天页右上角使用钱包接口显示可用积分；加载失败时不显示误导性数值。

## 验证

- 后端测试覆盖同一模型策略更新后仅新版本处于生效状态，以及按不同模型读取不同预占额度。
- 前端检查覆盖模型选择与积分指示的类型和构建。
