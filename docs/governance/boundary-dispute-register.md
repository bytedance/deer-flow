## 争议能力列表

### D-001：报告模板 DSL 内容归属

| 字段 | 内容 |
|------|------|
| **能力** | 行业报告模板的 DSL 定义内容 |
| **当前状态** | 暂归 Industry Solution Layer |
| **争议点** | 报告模板的 DSL 内容（如日报、周报、月报模板）包含行业知识，但其定义语言（DSL）是通用的。模板内容是否可作为租户级配置放在 Enterprise Control Plane？ |
| **观点 A**（归 Industry） | 模板 DSL 包含行业领域知识（设备类型、测点、阈值），本质是行业交付物 |
| **观点 B**（归 Enterprise） | 模板可由租户管理员通过 DSL 自行定义和发布，符合 Enterprise Control Plane 的"租户定制"特征 |
| **建议决策者** | 产品架构负责人 + 行业解决方案负责人 |
| **影响范围** | ISSUE-14（三层产品结构）中报告模块的代码目录归属 |

### D-002：闭环工单 SLA 模型

| 字段 | 内容 |
|------|------|
| **能力** | 闭环工单的 SLA 时限计算模型 |
| **当前状态** | 暂归 Enterprise Control Plane |
| **争议点** | 当前 SLA 是简单的优先级→小时数映射，属于通用工作流能力。但如果不同行业有不同 SLA 标准（如电力行业 vs 石化行业），是否需要行业层覆盖？ |
| **观点 A**（归 Enterprise） | SLA 是租户的运维策略，租户管理员可配置，不涉及行业专属逻辑 |
| **观点 B**（归 Industry） | 不同行业有不同的运维 SLA 标准（国标/行标），可能需要行业特有的 SLA 计算引擎 |
| **建议决策者** | 架构负责人 |
| **影响范围** | ISSUE-15（交付方式）中 SLA 模板的打包策略 |

### D-003：前端报告模板编辑器的层级归属

| 字段 | 内容 |
|------|------|
| **能力** | 报告模板 DSL 编辑器（`workspace/report-templates/` 前端页面） |
| **当前状态** | 暂归 Industry Solution Layer |
| **争议点** | DSL 编辑器是通用编辑器框架，可编辑任何 DSL 模板。但如果模板内容属于 Industry 层，编辑器的归属是否应该分离？ |
| **观点 A**（归 Core） | DSL 编辑器是通用 UI 组件，不包含行业逻辑 |
| **观点 B**（归 Industry） | 编辑器与行业模板强耦合（特定字段、校验规则、预览逻辑） |
| **建议决策者** | 前端架构负责人 |
| **影响范围** | ISSUE-14（三层产品结构）中前端代码目录归属 |

### D-004：知识库行业文档的预置内容

| 字段 | 内容 |
|------|------|
| **能力** | 行业知识库的预置文档（设备手册、故障案例库等） |
| **当前状态** | 未在分类结论中单独列出 |
| **争议点** | 知识库基础设施（Core Platform）与行业知识内容（Industry Solution Layer）的边界清晰，但预置行业文档是否应作为产品交付物打包？ |
| **观点 A**（归 Industry） | 行业文档是行业交付物的一部分，属于 Industry Solution Layer |
| **观点 B**（归 Enterprise） | 租户可以自行上传和管理文档，预置内容属于租户 onboarding 模板 |
| **建议决策者** | 产品架构负责人 |
| **影响范围** | ISSUE-15（交付方式）中文档打包策略 |

## 已解决争议

以下能力在初步评审中存在分歧，经分析后已达成一致：

| 编号 | 能力 | 最终归属 | 解决理由 |
|------|------|----------|----------|
| R-001 | RPC 客户端框架 | Core Platform | `rpc_client.py` 是纯技术组件（HTTP重试/超时），与行业协议无关 |
| R-002 | InS 认证 Provider | Industry Solution Layer | 直接依赖 ins-base-rpc Java 服务，不可脱离行业系统运行 |
| R-003 | Skill 启用/禁用 | Enterprise Control Plane | 通过 `extensions_config.json` 租户级管理，不修改 Skill 本身 |
