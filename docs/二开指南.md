# DeerFlow 技术文档

> 面向：开发人员 · 架构师 · 项目经理 · CTO

---

## 1. 项目概述

### 1.1 什么是 DeerFlow

DeerFlow（Deep Exploration and Efficient Research Flow）是一个基于 LangGraph 的 **AI 超级智能体运行时平台**。它为大语言模型提供了完整的基础设施——沙箱执行、持久化记忆、子智能体委派、可扩展工具集——使 AI 能够自主完成复杂的多步骤任务。

**定位**：不是一个单一的 AI 应用，而是一个 **智能体编排引擎 + 多租户平台**，支持企业按需定制智能体、工具和技能。

### 1.2 核心价值

| 角色 | 价值 |
|------|------|
| CTO | 可私有化部署的 AI 平台，支持多模型、多租户、可审计 |
| 架构师 | 模块化设计，harness/app 分层，支持水平扩展 |
| 项目经理 | 低代码配置新智能体，无需改动核心代码 |
| 开发人员 | 清晰的扩展点（工具、技能、MCP、智能体），TDD 工作流 |

### 1.3 技术栈

```

│            Tailwind CSS 4 · TanStack Query · ECharts     │

```

### 2.2 分层设计

| 层级 | 包路径 | 职责 |
|------|--------|------|
| **Harness** | `deerflow.*` | 可发布的智能体框架（agent、tools、sandbox、models、MCP、skills、config） |
| **App** | `app.*` | 应用层（FastAPI Gateway、IM 渠道集成） |

**依赖规则**：App 可以导入 deerflow，但 deerflow 永远不导入 app。此边界由 CI 测试 `test_harness_boundary.py` 强制执行。

### 2.3 多租户架构

```
三级智能体发现（优先级从高到低）：
  User Agent > Tenant Agent > Builtin Agent

数据隔离：
  {base_dir}/users/{user_id}/          ← 用户数据
  {base_dir}/tenants/{tenant_id}/      ← 租户数据
  agents/builtin/                       ← 内置智能体
```

## 3. 功能模块

### 3.1 智能体系统

#### 功能描述

Lead Agent 是系统的核心入口，负责理解用户意图、调度工具、委派子智能体。每个智能体由 `config.yaml`（配置）和 `SOUL.md`（人格/行为准则）定义。

#### 数据流

```
用户消息 → Gateway API → RunManager → Lead Agent
  → 加载 SOUL.md 作为 system prompt
  → 加载 tools（sandbox + builtin + MCP + community）
  → 加载 skills（注入到 prompt）
  → 执行中间件链（18 个中间件）
  → 调用 LLM → 工具调用 → 返回结果
  → SSE 流式推送 → 前端渲染
```

#### 智能体层级（新功能）

支持 parent/children 层级关系：
- 父智能体 `type: group` — 点击后展示子智能体选择面板
- 子智能体 `parent: xxx` — 完整独立的智能体，有自己的 SOUL.md 和工具集
- 前端通过 `useAgentChildren(parentName)` hook 按 parent 字段过滤构建树

#### 二开指南

**新增一个智能体**：
```bash
# 1. 创建目录
mkdir agents/builtin/my-agent/

# 2. 编写 config.yaml
cat > agents/builtin/my-agent/config.yaml << 'EOF'
name: my-agent
display_name: "我的智能体"
icon: "🤖"
description: "描述智能体能力"
model: null
tool_groups:
  - bash
skills:
  - data-analysis
EOF

# 3. 编写 SOUL.md（系统提示词）
cat > agents/builtin/my-agent/SOUL.md << 'EOF'
# 我的智能体
你是一个专业的 xxx 助手。
## 核心职责
- ...
## 行为准则
- ...
EOF

# 4. 重启服务，智能体自动被扫描加载
```

### 3.2 工具系统

#### 功能描述

工具是智能体与外部世界交互的接口。系统支持多种工具来源：

| 来源 | 说明 |
|------|------|
| Config 定义 | `config.yaml` 中通过 `tools[]` 配置 |
| MCP 服务器 | 通过 `extensions_config.json` 配置的外部工具服务 |
| 内置工具 | `present_files`、`ask_clarification`、`view_image`、`http_connector` |
| 社区工具 | Tavily（搜索）、Jina AI（抓取）、Firecrawl（爬虫） |
| 子智能体工具 | `task` — 委派任务给子智能体 |

#### 数据流

```
Lead Agent 决定调用工具
  → ToolErrorHandlingMiddleware 包装异常
  → GuardrailMiddleware 权限检查
  → 工具执行（可能涉及沙箱路径翻译）
  → 返回 ToolMessage
  → Lead Agent 继续推理
```

#### 二开指南

**新增一个自定义工具**：

```python
# 1. 在 deerflow/tools/ 下创建工具模块
# backend/packages/harness/deerflow/tools/my_tool.py

from langchain_core.tools import tool

@tool
def my_custom_tool(query: str) -> str:
    """工具描述（LLM 会看到这段文字来决定是否调用）"""
    # 实现逻辑
    return result

# 导出变量
tools = [my_custom_tool]
```

```yaml
# 2. 在 config.yaml 中注册
tools:
  - use: "deerflow.tools.my_tool:tools"
    group: "my-tools"

tool_groups:
  - name: "my-tools"
    description: "我的自定义工具集"
```

### 3.3 技能系统

#### 功能描述

技能（Skills）是注入到智能体 system prompt 中的知识模块，以 Markdown 文件形式存在。技能不是代码，而是指导智能体如何完成特定任务的"说明书"。

#### 数据流

```
智能体启动
  → load_skills() 扫描 skills/{public,custom}/
  → 读取 SKILL.md 的 YAML frontmatter（name, description, allowed-tools）
  → 检查 extensions_config.json 中的 enabled 状态
  → 将启用的技能内容注入 system prompt
  → LLM 根据技能指导执行任务
```

#### 二开指南

**新增一个技能**：

```bash
# 1. 创建技能目录
mkdir skills/custom/my-skill/

# 2. 编写 SKILL.md
cat > skills/custom/my-skill/SKILL.md << 'EOF'
---
name: my-skill
description: "技能描述"
allowed-tools:
  - bash
  - web_search
---

# 我的技能

## 使用场景
当用户要求 xxx 时使用此技能。

## 执行步骤
1. 第一步...
2. 第二步...

## 输出格式
...
EOF

# 3. 在 extensions_config.json 中启用
# 或通过 API: PUT /api/skills/my-skill { "enabled": true }
```

### 3.4 沙箱系统

#### 功能描述

沙箱为智能体提供隔离的代码执行环境，防止恶意操作影响宿主系统。

| 模式 | 实现 | 适用场景 |
|------|------|----------|
| Local | LocalSandboxProvider | 开发环境，单用户 |
| Docker | AioSandboxProvider | 生产环境，多用户隔离 |
| Kubernetes | Provisioner (port 8002) | 大规模部署 |

#### 数据流

```
智能体调用 bash/write_file 等工具
  → SandboxMiddleware 获取沙箱实例
  → 虚拟路径翻译：/mnt/user-data/... → 物理路径
  → 在沙箱中执行命令
  → SandboxAuditMiddleware 记录审计日志
  → 返回执行结果
```

#### 虚拟路径映射

```
Agent 视角                          物理路径
/mnt/user-data/workspace    →    .deer-flow/users/{uid}/threads/{tid}/user-data/workspace
/mnt/user-data/uploads      →    .deer-flow/users/{uid}/threads/{tid}/user-data/uploads
/mnt/user-data/outputs      →    .deer-flow/users/{uid}/threads/{tid}/user-data/outputs
/mnt/skills                 →    deer-flow/skills/
```

### 3.5 记忆系统

#### 功能描述

长期记忆系统让智能体能够跨会话记住用户偏好、知识和上下文。

#### 数据流

```
对话进行中
  → MemoryMiddleware 过滤消息（用户输入 + 最终 AI 回复）
  → 入队到 MemoryQueue（30s 防抖）
  → 后台线程调用 LLM 提取事实和上下文
  → 原子写入 memory.json（去重）
  → 下次对话时注入 <memory> 标签到 system prompt
```

#### 存储结构

```json
{
  "userContext": { "workContext": "...", "personalContext": "...", "topOfMind": "..." },
  "history": { "recentMonths": "...", "earlierContext": "...", "longTermBackground": "..." },
  "facts": [
    { "id": "...", "content": "用户偏好使用 Python", "category": "preference", "confidence": 0.9 }
  ]
}
```

### 3.6 MCP 集成

#### 功能描述

MCP（Model Context Protocol）允许接入外部工具服务器，扩展智能体能力而无需修改代码。

#### 数据流

```
extensions_config.json 定义 MCP 服务器
  → MultiServerMCPClient 懒加载连接
  → 工具列表缓存（mtime 失效）
  → Lead Agent 绑定 MCP 工具
  → 调用时通过 stdio/SSE/HTTP 传输
  → OAuth 自动刷新 token（HTTP/SSE 模式）
```

#### 二开指南

```json
// extensions_config.json
{
  "mcpServers": {
    "my-server": {
      "enabled": true,
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@my-org/mcp-server"],
      "description": "我的 MCP 服务器"
    }
  }
}
```

### 3.7 IM 渠道集成

#### 功能描述

支持将智能体接入企业 IM 平台，用户通过聊天窗口直接与智能体对话。

| 平台 | 协议 | 特性 |
|------|------|------|
| 飞书/Lark | WebSocket | 卡片流式更新 |
| Slack | Socket Mode | 同步等待响应 |
| Telegram | Long-polling | Bot API |
| 钉钉 | Stream Push | AI Card 流式 |
| 企业微信 | WebSocket | — |
| 微信 | iLink Long-polling | — |

#### 数据流

```
IM 平台消息 → Channel 实现 → MessageBus.publish_inbound()
  → ChannelManager 查找/创建 thread
  → 通过 LangGraph SDK 调用 Gateway API
  → 流式/同步获取 AI 响应
  → 通过 Channel 回复用户
```

```

  → stream events 更新 thread state
  → TanStack Query 管理缓存
  → MessageList 渲染消息
  → ArtifactPanel 渲染产物
```

## 4. 中间件链

Lead Agent 的中间件按严格顺序执行，每个中间件负责一个关注点：

| # | 中间件 | 职责 |
|---|--------|------|
| 1 | ThreadDataMiddleware | 创建线程目录，用户隔离 |
| 2 | UploadsMiddleware | 注入上传文件信息 |
| 3 | SandboxMiddleware | 获取沙箱实例 |
| 4 | DanglingToolCallMiddleware | 处理中断的工具调用 |
| 5 | LLMErrorHandlingMiddleware | LLM 调用错误恢复 |
| 6 | GuardrailMiddleware | 工具调用权限检查 |
| 7 | SandboxAuditMiddleware | 沙箱操作审计 |
| 8 | ToolErrorHandlingMiddleware | 工具异常转为错误消息 |
| 9 | SummarizationMiddleware | 上下文压缩 |
| 10 | TodoListMiddleware | 任务跟踪（Plan Mode） |
| 11 | TokenUsageMiddleware | Token 用量统计 |
| 12 | TitleMiddleware | 自动生成对话标题 |
| 13 | MemoryMiddleware | 记忆提取入队 |
| 14 | ViewImageMiddleware | 图片注入（视觉模型） |
| 15 | DeferredToolFilterMiddleware | 延迟工具过滤 |
| 16 | SubagentLimitMiddleware | 子智能体并发限制 |
| 17 | LoopDetectionMiddleware | 循环检测与强制终止 |
| 18 | ClarificationMiddleware | 澄清请求中断 |

## 5. API 接口

### 5.1 核心端点

| 模块 | 端点 | 说明 |
|------|------|------|
| 智能体 | `GET /api/agents` | 三级合并列表（含 type/parent） |
| 智能体 | `PUT /api/agents/{name}/enabled` | 启用/禁用 |
| 智能体 | `POST /api/agents/fork/{name}` | Fork 到用户目录 |
| 对话 | `POST /api/threads/{id}/runs/stream` | 创建运行 + SSE 流 |
| 对话 | `GET /api/threads/{id}/runs/../messages` | 获取消息历史 |
| 技能 | `GET /api/skills` | 列出所有技能 |
| 技能 | `POST /api/skills/install` | 安装 .skill 包 |
| MCP | `GET /api/mcp/config` | 获取 MCP 配置 |
| MCP | `PUT /api/mcp/config` | 更新 MCP 配置 |
| 记忆 | `GET /api/memory` | 获取记忆数据 |
| 模型 | `GET /api/models` | 列出可用模型 |
| 上传 | `POST /api/threads/{id}/uploads` | 上传文件 |
| 租户智能体 | `POST /api/tenants/{id}/agents` | 创建租户智能体 |
| 租户 MCP | `POST /api/tenants/{id}/mcp-servers` | 创建租户 MCP |

### 5.2 Nginx 路由

```
/api/langgraph/*  →  Gateway :8001（重写为 /api/*）
/api/*            →  Gateway :8001
/                 →  Frontend :3000
```

## 6. 配置系统

### 6.1 配置文件

| 文件 | 位置 | 用途 |
|------|------|------|
| `config.yaml` | 项目根目录 | 主配置（模型、工具、沙箱、记忆等） |

### 6.2 模型配置示例

```yaml
models:
  - name: "default"
    display_name: "GPT-4o"
    use: "langchain_openai:ChatOpenAI"
    model: "gpt-4o"
    api_key: $OPENAI_API_KEY
    base_url: "https://api.openai.com/v1"
    supports_thinking: false
    supports_vision: true
```

### 6.3 环境变量

所有配置值支持 `$ENV_VAR` 语法引用环境变量，敏感信息（API Key 等）不应硬编码。

## 7. 部署

### 7.1 部署方式

| 方式 | 命令 | 适用场景 |
|------|------|----------|
| 本地开发 | `make dev` | 开发调试 |
| Docker 开发 | `make docker-start` | 团队协作开发 |
| Docker 生产 | `make up` | 生产部署 |
| 本地守护进程 | `make dev-daemon` | 后台运行 |

### 7.2 硬件要求

| 场景 | 最低配置 | 推荐配置 |
|------|----------|----------|
| 本地开发 | 4 vCPU, 8 GB RAM | 8 vCPU, 16 GB RAM |
| 生产部署 | 8 vCPU, 16 GB RAM | 16 vCPU, 32 GB RAM |

### 7.3 安全注意事项

- 默认绑定 127.0.0.1，仅本地访问
- 跨网络部署需配置：IP 白名单、认证网关、网络隔离
- Gateway 强制活跃内容类型（HTML/SVG）为下载附件（防 XSS）
- 沙箱提供代码执行隔离

## 8. 二次开发指南

### 8.1 新增智能体（最常见）

1. 在 `agents/builtin/` 下创建目录
2. 编写 `config.yaml`（名称、图标、描述、工具组、技能）
3. 编写 `SOUL.md`（系统提示词）
4. 重启服务，自动加载

**无需修改任何代码。**

### 8.2 新增工具

1. 在 `backend/packages/harness/deerflow/tools/` 下创建 Python 模块
2. 使用 `@tool` 装饰器定义工具函数
3. 在 `config.yaml` 的 `tools[]` 中注册
4. 在 `tool_groups[]` 中分组

### 8.3 新增技能

1. 在 `skills/custom/` 下创建目录
2. 编写 `SKILL.md`（YAML frontmatter + Markdown 内容）
3. 通过 API 或 `extensions_config.json` 启用

### 8.4 接入新 MCP 服务器

1. 在 `extensions_config.json` 的 `mcpServers` 中添加配置
2. 支持 stdio/SSE/HTTP 三种传输方式
3. 支持 OAuth token 自动刷新

### 8.5 新增 IM 渠道

1. 在 `app/channels/` 下创建渠道实现
2. 继承 `Channel` 基类，实现 `start/stop/send`
3. 在 `config.yaml` 的 `channels` 中配置

### 8.6 新增前端页面

1. 在 `frontend/src/app/` 下按 Next.js App Router 规范创建路由
2. 使用 `core/` 下的 hooks 获取数据
3. 使用 `components/ui/` 的 Shadcn 组件构建 UI
4. 添加 i18n 翻译键
