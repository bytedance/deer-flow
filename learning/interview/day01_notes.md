## 后端复习与口述

围绕 Python list（动态数组）、链表和 dict（哈希表）复习：

1. 为什么 list 按下标访问和按值查找的复杂度不同？
2. “链表插入是 O(1)”依赖什么前提？把寻找插入位置算进去会怎样？
3. dict 查找的平均复杂度与最坏复杂度分别是什么？两数之和用它换来了什么、付出了什么？

我的回答（根据对话整理）：

- 按下标可以直接定位对应位置；按值查找需要遍历，目标在末尾或不存在时最坏 O(n)。Python list 连续排列的是元素引用。
- 列表在下标 0 插入时，原有元素引用都需要后移，最坏 O(n)，元素的数值本身不变。
- 链表在已知节点后插入只需修改连接，是 O(1)；只有头节点时，寻找尾节点需要从头遍历，整体插入最坏 O(n)。这里不必使用递归，循环遍历只需要 O(1) 额外空间。
- 字典应以需要查询的数值作为 key、以需要取得的下标作为 value。字典查找平均 O(1)、最坏 O(n) 的区别已讲解，尚待独立复述；普通递归遍历链表的调用栈开销也待复述。

复习速查：

| 结构与操作 | 时间复杂度 |
| --- | --- |
| list 按下标访问 | O(1) |
| list 按值查找 | 最坏 O(n) |
| list 在头部或中间插入 | 最坏 O(n) |
| 链表在已知节点后插入 | O(1)，不包含寻找节点 |
| 仅有头节点时寻找链表尾节点 | O(n) |
| dict 按 key 查找 | 平均 O(1)，最坏 O(n) |
