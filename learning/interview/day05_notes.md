## 题意

给定无序整数列表 nums，返回最长连续整数序列的长度，要求时间 O(n)。连续看数值是否相差 1，与原列表位置无关；重复值不额外增加长度。

```python
nums = [100, 4, 200, 1, 3, 2]
# 连续整数 1、2、3、4 的长度为 4。
```

官方范围：0 <= n <= 100000，数值范围 -10^9 到 10^9，允许负数、重复值及空列表。

## 当前思路问题

快速查询问题已回答：学习者提出字典，key 为数字、value 为出现次数。用数字作 key 查询存在性是可行思路；本题不需要频次，助手进一步介绍 set(nums) 保存互不重复的数字，通过 x in numbers 判断成员，平均 O(1)。集合方案来自提示，不记为学习者独立提出；集合不保证排序。

起点问题已回答：助手提出只从每段起点扫描的目标，学习者给出“x-1不存在”，判断正确。若前一个数存在，当前数属于已经有更早起点的连续段；前一个数不存在则可以从当前数开始。

实现指导：先建立去重集合和最长长度变量；遍历集合，仅对起点向后计数；每段从当前数和长度 1 开始，每找到下一个连续数就推进并增加长度；记录各段最大值，最后返回。外层遍历集合，避免重复的起点在原列表中引发重复扫描；空列表应返回 0。助手未代写完整算法。

## 第二版验证与时间复杂度

学习者自行改为 result = 0；遍历去重集合，只在 x-1 不存在时设 cur = 1，使用 while x+1 in num 向后递增 x 和 cur，最后 result = max(result, cur)。修改后的逻辑正确。函数外层的 cur = 0 可省略，但不影响结果；循环内给 x 加一不修改集合，也不改变 for 的迭代器。

助手本机验证 12/12 通过：首版的 8 个用例全部通过，另覆盖全重复 [7,7,7]、正负数值上下界附近的两段、100000 个数字的降序连续段，以及 50000 个重复起点加上后续 50000 个连续数字（总输入 100000，答案 50001）。上限输入用于正确性和规模验证，不以运行耗时作为复杂度证明。助手未代改算法源码。

学习者提问嵌套循环是否仍为 O(n)。本次说明：设去重后有 u 个数字、g 个连续段，外层遍历 u 次，每段只从起点展开，内层循环体累计 u-g 次，包含每段结束时的失败查询也仅 O(u)。建立集合按平均 O(n)，集合插入/成员查询按平均 O(1)，因此总时间 O(n+u)=O(n)。外层仍会遇到非起点，if 条件使这些元素不再展开，不能把每次外层都视为一次完整内层扫描。

循环计数讨论：助手曾问集合为 1 到 100 时内层循环体累计次数，学习者转而正确指出即使 x=2 也要执行一次外层 if 判断。已澄清此前“0 次”专指内层循环体，不代表本轮无操作；外层 if 检查仍计入 O(n)。以 1 到 5 为例，外层 if 共 5 次、while 条件共 5 次、while 循环体共 4 次。学习者随后用 O(2n) 与 O(n) 同阶理解常数省略，方向正确；已补充操作数不必精确等于 2n。完整累计次数解释仍留作复习，不据此记为独立证明通过。

## 空间复杂度纠正

学习者回答“O(1)，没有用额外的数据结构存储数据”。漏算了 num = set(nums) 新建的集合；该语句不在原列表上原地去重。设不同数字有 u 个，集合保存 u 个元素条目，额外空间随 u 增长；最坏所有数字不同，u=n，故额外空间 O(n)。输入列表 nums 本身不计入额外空间，result、cur、x 等固定数量变量只占 O(1)。

学习者进一步回答“只有输入的n个数字都相同才是O(1)，不然都是和n相关”。已注意到集合元素数量的影响，但“只有全相同”条件过强。助手补充：若输入始终只含 1 和 2，不论 n 如何增长，集合最多两个元素，也可按 O(1) 分析；一般按不同数字数量 u 写 O(u)，最坏 u=n，因此本题最坏额外空间 O(n)。上述修正由助手说明，仍保留独立复述任务。
