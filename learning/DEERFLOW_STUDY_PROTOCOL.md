# DeerFlow 学习会话协议

本协议实现用户明确要求的课程入口：在 DeerFlow 项目中说“开始学习”进入课程，说“结束今天的学习”结束会话；助手组织中间流程。默认中文，用户背景为熟悉 Python 和后端开发，每次参考 90 分钟。

## 适用范围与记录

- 本协议只用于 DeerFlow 学习。讨论、引用或编辑这两个词不算执行口令；创建学习计划也不算开始第一课。
- 唯一学习路线、目标与验收：[核心源码阅读路线](deerflow-book/DeerFlow核心源码阅读路线.md)。其他学习计划已按用户要求删除，不新建平行课程。
- 当前状态、掌握证据和历史：[学习日志](learn-codebase-journal.md)。这是唯一进度来源；不另建第二份进度文件。
- 阅读源码和实作时继续遵守根及模块 AGENTS.md。不要改 CLAUDE.md。
- 当前任务中用户的新要求优先于旧计划。旧企业/算法轮换不自动进入此课程。仅在学习者明确指定相应项目时恢复其独立记录。

## 开始学习

当用户明确发送“开始学习”或同义续学请求：

1. 读取日志的当前状态、相关复习和最近源码停点，再读取核心源码路线中当前目录/模块。首次读取必要背景，之后按需加载，避免每次重读所有学习资料。
2. 若已有进行中的会话，恢复同一个会话与待答题；不因重复开始口令增加次数。若上次已结束，创建下一会话，编号为 `S001`、`S002` 等。同一天再次开始可以是新会话，以序号区分。
3. 使用 Asia/Shanghai 的用户日期。用户没有更改时沿用 90 分钟，不重复询问背景、时间和目标。会话编号按实际开启次数增加，不能拿日期差当学习次数。
4. 从未完成的源码逻辑块继续。简短回顾相关薄弱点，说明当天阅读目标和模块成果，再定位文件/函数进入源码；复习问题不阻塞继续阅读。不按已删除的DF课程从头排课。
5. 确认当次需要的源码、模块指南、测试与环境。先读工作区现状，保留已有改动；不覆盖实际配置或把上游文档当成本地代码事实。版本变化只核对受影响知识点。
6. 在日志中保存会话状态为“进行中”、当前单元、参考时长、阅读目标和精确源码停点。给简短开场，展示当前真实代码段并讲解；需要复习或模块验收时再留一道明确问题，等待真实回答。

开场示例结构：今天是第几次会话；从哪个单元和停点继续；今天要完成什么。不要先输出整套课程或完整答案。

## 中间教学与技能调度

用户已授权本课程按需使用下列三个技能。实际使用前读其已安装 SKILL.md，技能引用资源按需读取：

- `codebase-onboarding`：首次地图、阶段整合或架构变化时使用。已有资料能回答的小问题直接复用，不运行完整仓库调查。
- `how`：讲解一个模块或执行链。通常使用 Explain，给出源码位置、输入输出、状态及代表性异常分支。遵守其只读探索约定；子代理只研究当前问题，不能替用户回答练习。
- `learn-codebase`：主动回忆、预测、提示、迁移练习与记录。虽然它单独设置为手动触发，本课程会显式选择并读取它；无需用户每天写技能名，也不修改其全局调用策略。

当前安装根为 `C:/Users/Administrator/.codex/skills`。优先使用当前环境技能目录提供的位置；迁移环境时按技能名查找，缺失时如实说明并继续可完成的教学，不声称加载了不可用技能。课程、日志和源码事实足以支撑常规续学；不自行安装替代技能。

教学节奏：

1. 每轮围绕一个连贯源码段讲解，按用户需要逐行展开；在模块结束或关键分支处做少量预测/复述，不用连续猜变量或填空代替源码。不能替用户编造答案、完成记录或掌握程度。
2. 以熟悉 Python 后端为起点，只有真实卡点暴露时才补基础。解释图和伪代码要与具体文件、函数对应。
3. 提示逐级增加：指出观察点 → 缩小分支 → 给局部示例。两三轮仍卡住时直接解释必要部分，再出一个相似变化检查；不要无限追问。
4. 编码练习先让用户提出接口、场景或代码。助手可以准备合成输入、解释测试设施、给局部骨架；用户要求完整示例或代写时可以提供，但在日志注明贡献来源，另设独立迁移检查。
5. 读源码、离线实验和真实运行分别记录。Mock 通过不等于真实服务、沙箱或模型已验证；用户报告的结果与助手工具核验的结果也要分开。
6. 遇到缺少环境或外部服务时，继续无依赖的源码和替身练习，记录真实运行待办。是否安装、启动、写入外部服务等按用户授权和项目约定处理；本协议不额外授予发布或发送消息权限。
7. 功能与缺陷练习遵守仓库 TDD、文档和验证要求。前端主机侧 pnpm 命令经 `scripts/pnpm.py`；Python 文本读写显式 UTF-8。
8. 每完成一个有意义的问答或实践，及时更新日志；写下具体回答、提示次数、代码作者和验证结果。普通状态追问只需简短回答，然后继续当前任务。
9. 90 分钟是工作量参考。不得声称仅凭消息数量知道实际耗时。能核验时间时临近预算提示收尾；用户想继续可继续。若时间无法可靠估计，以完成量和用户结束口令为准。

### 按核心源码路线阅读（2026-10-23 按用户最新偏好修订）

- 学习者明确更喜欢此前阅读worker的形式，并要求按项目文件夹分类。只执行核心源码阅读路线：agents、models、runtime、sandbox、subagents、tools系统精读，补config和backend/app/gateway；其他目录按专题或代表实现读。以真实源码逐段/按需逐行为主要教材，不恢复已删除的12阶段60单元课程。
- 每次恢复说明 R 编号、文件、函数和当前逻辑块，补简短调用关系后直接讲解代码；通常一次展示约 10～40 行，按复杂度调整。用户追问优先，不强制先猜每个变量。
- 核心函数按控制流连续读；跟进辅助函数前记下返回位置，解释后回到主函数。深度区分职责定位、执行追踪和验证修改，允许用户要求的逐行阅读，不把“无需通篇读完”理解成不应精读。
- 已讲过的worker流处理、批处理和seq等记录保留。当前按日志先读runs/schemas.py，再补RunRecord/RunContext，返回run_agent构建Agent段并进入assemble_lead_agent；不重置到第一课。
- 复述、变化题和测试用于模块验收与迁移，不代替主要源码讲解。未答的 await 填空等保留为后续复习，不要求答完才开始阅读。
- 助手核对实际源码、必要日志和对应测试位置；源码、合成示例与真实运行分别记录。环境待办不阻塞源码学习。
- 精确停点必须包含文件、符号及下一逻辑块；规划调整和教师解释不提升单元等级。

## 结束今天的学习

当用户明确说“结束今天的学习”或同义停止学习请求：

1. 立即停止新增讲解、题目和编码任务。即使阶段测验未完成，也不得要求用户先答完才能结束。
2. 将本次证据归档到日志：覆盖主题、用户回答、提示情况、实际代码/命令/结果、尚未验证范围、未完成任务和精确停点。
3. 更新源码模块阅读状态、理解证据与复习队列。只有证据满足路线标准才晋级；没有回答的题保持待答，已经讲解不等于已经掌握。
4. 将当前会话状态改为“已结束”，保存下一次的首个复习或实践动作。未完成单元仍为当前单元，不把结束一天当成完成单元。
5. 向用户简短报告：今天做到哪里；掌握与卡点；下次从哪里继续；日志已保存。结束回复不再附带要求当天完成的新问题。

如果没有进行中的正式会话，只保存已有未归档内容，说明当前停点；不虚构课程、不增加完成次数。重复结束口令不重复追加同一份学习记录或推进进度。

## 状态恢复与晋级

- 会话状态：待开始 → 进行中 → 已结束。源码模块和会话序号独立。
- 模块状态：未开始、阅读中、待复习、已验证。区分已讲解、独立解释和独立修改验证，不按旧DF总数或阶段晋级。
- 旧DF单元与L0–L3等级保留为历史证据，不删除学习成果，也不重新启用旧课程。
- 日志顶部保留当前会话摘要；历史记录追加到 Session Log，保留已验证事实与来源。不要覆盖别的项目笔记。
- 复习以成功回忆后的 1 天、3 天、1 周、2 周作为参考；失败则缩短间隔。到期项目很多时优先挑与当前主题相关或最薄弱的 1～2 项，避免复习占满整次会话。
- 忘记结束或聊天中断时，下一次恢复未结束会话，依据记录校对待答任务。记录不完整时标明缺失，不推测用户已完成。
- 换聊天但仍在本仓库时，依靠根 AGENTS.md、计划和日志恢复。移动仓库时相对路径继续有效，技能位置重新解析。
- 模块验收时做一个相关变化检查，并适量复习前面代码。助手解释正确、代写测试通过、用户说“懂了”均不能单独证明独立掌握。
- 满足核心路线中的二次开发验证目标后保存证据与剩余边界；未来版本变化可开展专题续学，不把路线读完直接等同于学透。

本流程是由聊天口令启动的学习约定。复习日期只用于会话内选择题目，不创建定时任务、提醒或后台工作。
