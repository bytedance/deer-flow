## 启动和停止

在 PowerShell 中先执行以下公共准备：

```powershell
cd F:\harness-learn\deer-flow
$env:DEER_FLOW_ROOT = (Get-Location).Path.Replace('\', '/')
$deerflowCompose = @('-p', 'deer-flow-dev', '-f', 'docker/docker-compose-dev.yaml', '-f', 'logs/bootstrap/compose.mirror.yaml')
```

之后按需要执行一条命令：

```powershell
# 使用已构建镜像启动
docker compose @deerflowCompose up --no-build -d redis frontend gateway nginx

# 查看服务状态
docker compose @deerflowCompose ps

# 停止服务，保留数据
docker compose @deerflowCompose stop

# 修改 .env 中的密钥后，重新创建后端容器以加载环境变量
docker compose @deerflowCompose up --no-build -d --force-recreate gateway

# 需要重新安装依赖或重建镜像时
docker compose @deerflowCompose up --build -d redis frontend gateway nginx
```

## 本机的下载兼容处理

首次启动时 Docker Hub 出现 TLS 握手超时。改用 `public.ecr.aws/docker/library/` 获取 Nginx、Python、Node 和 Docker CLI 基础镜像，随后构建成功。Nginx 的镜像摘要与最初请求的镜像一致，并已在本地标记为 `nginx:alpine`。

构建覆盖文件位于 `logs/bootstrap/compose.mirror.yaml`，配套的两个 Dockerfile 也在该目录，只替换了基础镜像来源。仓库原始 Dockerfile 未修改。这个目录受 Git 忽略；清理 `logs` 时需要保留 `bootstrap` 才能继续使用上述命令。若以后修改原始 Dockerfile，需要同步更新这两个本地副本。

## 配置、日志和数据

- `config.yaml`：模型与 Sandbox 配置。
- `.env`：`DEEPSEEK_API_KEY` 等环境变量，勿提交或复制到聊天中。
- `extensions_config.json`：目前为空的可选扩展配置。
- `logs/gateway.log`、`logs/frontend.log`：运行日志。
- `logs/docker-start.log`：本次构建与启动日志。
- `backend/.deer-flow/`：本次运行生成的数据库等持久化数据。

当前配置使用 `LocalSandboxProvider`。因为后端运行在 Docker 中，这里的“本地”指后端容器内的环境；访问宿主机文件需要通过已挂载目录。当前未启动独立 Sandbox 容器或 Kubernetes Provisioner。

本次完成环境启动与模型连通性验证，不代表第四章学习或二次开发实作已完成。学习仍从已保存的 `ToolRuntime` 参数设计问题继续。
