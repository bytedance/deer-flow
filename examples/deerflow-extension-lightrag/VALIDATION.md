project (青杉计划), funded by Star River Laboratory (星河实验室). A dedicated

The initial extraction with default GLM reasoning remained in processing for

with `OPENAI_LLM_EXTRA_BODY='{"thinking":{"type":"disabled"}}'`,
`OPENAI_LLM_MAX_TOKENS=6000` and `ENTITY_EXTRACTION_USE_JSON=true`. Recovery of
the same document completed successfully. No provider adapter code or source
mapping was changed to make the live responses pass. These settings are local
validation choices, not new DeerFlow defaults.

  `E2E_LLM_BASE_URL`, `E2E_LLM_API_KEY`, `WEKNORA_KNOWLEDGE_BASE_ID` and
  `KNOWLEDGE_MODEL_QUESTION`. The question should cover attributable facts in

From the repository root:

```sh
uv run --no-sync --project backend pytest \
  backend/tests/test_knowledge_phase1_live.py -m live -q --override-ini=addopts=
```

Tests are read-only and require already indexed fixtures; they do not upload,
create pages, or change upstream credentials. The generative check has a
separate opt-in and incurs model API usage. Without it, only the provider checks
run. No credentials or raw API responses should be added to this record.

## Browser fixes and re-acceptance

The two chat issues above were reproduced and fixed on 2026-10-20:

- WeKnora's lexical Wiki endpoint returned no pages for the complete query
  `青杉 计划 负责人 资助机构 林岚 星河实验室`. The extension now retries an
  empty successful result with up to four distinct whitespace-separated keywords
  of at least two characters, keeping the same authorized KB and credentials.
  Duplicate title/excerpt pairs are merged. Schema, authorization and HTTP errors
  still fail immediately; nonempty original results do not trigger fallback.
- The local GLM-compatible proxy ignores the native `thinking.type=disabled`
  switch. Direct synthetic probes reproduced reasoning embedded in content with
  that payload. The same endpoint returned clean content with the chat-template

  no frontend text stripping or global change to official GLM profiles was made.

```yaml
# For the tested proxy's glm-5.3 deployment, not a universal GLM default.
extra_body:
  chat_template_kwargs:
    enable_thinking: false
```

## Limits

This validates provider retrieval, real model/tool/evidence execution and local
browser chat replay. It is not a concurrency/load test or production
authorization audit. Source forwarding is tested through the shared helper;
no second generative subagent was launched in this live run.

Relation evidence consists of upstream one-edge paths. Multi-hop discovery,
graph completeness, WeKnora entity-graph HTTP access, graph visualization and
management pipelines remain outside this delivery. Upstream extraction during
fixture preparation does not implement DeerFlow's planned Phase 2 pipeline.

## Shared-evidence budget review follow-up

The adapter now emits each referenced chunk ID once, before its first edge,
and labels every edge with the corresponding result positions. A regression
with 20 edges sharing a long chunk preserves all 20 edges under the shared
8,000-character budget with one source record. A second regression covers
partially shared chunks, missing IDs and prefix truncation without dangling
references. Graph descriptions remain unattributed; only original chunk text
receives a source citation.
