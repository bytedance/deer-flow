# Java RPC 客户端

## 目的

提供声明式 Java RPC 服务调用能力，支持配置定义的服务、Nacos 服务发现查找、超时重试以及结构化错误处理。

## 新增需求

### 需求：声明式服务定义

系统必须允许在 `config.yaml` 的 `rpc.services` 段中以声明方式定义 Java RPC 服务，每个服务包含服务名称、base URL 或 Nacos 发现引用，以及端点定义。

#### 场景：定义包含端点的 Java 服务
- **当** `config.yaml` 包含一个 `rpc.services` 条目，其中有 `name`、`discovery`（nacos 服务名称）和 `endpoints`（方法/路径/HTTP方法三元组列表）
- **则** RPC 客户端可以解析并调用这些端点

### 需求：服务发现查找

系统必须在配置了 `discovery` 时通过 Nacos 解析 Java 服务地址，然后再发起 RPC 调用。

#### 场景：通过 Nacos 解析服务
- **当** RPC 调用目标服务的配置为 `discovery: some-java-service`
- **则** 客户端向 Nacos 查询 `some-java-service` 的健康实例，并使用轮询选择一个

#### 场景：回退到直接 URL
- **当** RPC 调用目标服务使用直接的 `base_url` 而非 `discovery`
- **则** 客户端直接将请求发送到配置的 URL，不进行 Nacos 查找

### 需求：RPC 方法调用

系统必须提供 Python API 来调用 Java 服务方法，支持带类型的参数，并返回反序列化的 JSON 响应。

#### 场景：调用 Java RPC 方法
- **当** 执行 `rpc_client.call("user-service", "getUserById", {"id": 123})`
- **则** 客户端向解析后的服务 URL 发送 HTTP POST，JSON 请求体为 `{"id": 123}`，并返回解析后的 JSON 响应

#### 场景：服务中找不到方法
- **当** RPC 调用目标端点未在服务配置中定义
- **则** 客户端抛出明确的错误，提示该方法未配置

### 需求：超时和重试

系统必须支持可配置的超时和 RPC 调用自动重试。

#### 场景：请求超时
- **当** RPC 调用超过配置的超时时间（默认 30 秒）
- **则** 客户端抛出超时错误

#### 场景：瞬时故障重试
- **当** RPC 调用因 5xx 状态码或网络错误失败，且配置了重试
- **则** 客户端按配置的尝试次数进行退避重试

### 需求：错误处理

系统必须将 Java 服务错误转换为包含结构化错误信息的 Python 异常。

#### 场景：Java 服务返回错误
- **当** Java 服务返回 4xx 或 5xx 状态
- **则** 客户端抛出包含状态码和响应体的异常，以便调试

#### 场景：网络错误
- **当** Java 服务不可达（连接被拒绝、DNS 解析失败）
- **则** 客户端在重试耗尽后抛出连接错误
