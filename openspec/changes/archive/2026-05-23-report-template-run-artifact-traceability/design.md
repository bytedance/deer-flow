## Context

报告生成链路是 DeerFlow 的核心价值产出。当前模板、运行和产物之间缺少可追踪的元数据关联，导致无法回答审计类问题。需要建立完整的血缘链路。

## Goals / Non-Goals

**Goals:**
- 每次 report run 记录模板版本、触发上下文、知识来源
- 报告产物可回溯到 report run
- 三类失败场景（模板失效、知识不可用、运行中断）有清晰错误语义

**Non-Goals:**
- 不实现报告内容的 diff/版本对比
- 不涉及报告的审批工作流

## Decisions

### 决策 1：Run Metadata 作为不可变记录

- **选择**：每次 report run 生成时快照模板版本和知识来源，写入不可变的 run metadata
- **替代方案**：运行时动态查询 → 模板变更后历史记录不可追溯
- **理由**：不可变快照确保历史报告的上下文永远可回溯

### 决策 2：产物关联 run_id 而非直接关联模板

- **选择**：产物 → run → 模板的二级间接关联
- **替代方案**：产物直接关联模板 → 丢失了运行时的具体上下文
- **理由**：run 作为中间层可携带运行时的动态信息（知识库版本、参数等）

## Risks / Trade-offs

- [风险] Run metadata 存储增长 → 定期归档历史 run metadata
- [风险] 模板频繁变更导致 metadata 版本碎片化 → 只记录主版本号
