## 1. 准备 Workshop

- [x] 1.1 确定 Workshop 参与人：产品负责人、架构负责人、前端负责人、运行时负责人、网关负责人
- [x] 1.2 预定 2-3 次集中 Workshop 时间（每次 2-3 小时）
- [x] 1.3 收集各团队当前对 thread、run、upload、artifact、knowledge base、report run、closure ticket 的定义和使用现状
- [x] 1.4 准备 Workshop 材料：现有模块清单、当前各模块对象模型差异对照表

## 2. Workshop 1：主流程对齐

- [x] 2.1 绘制第一版"任务/对话 → 工具/知识 → 报告/产物 → 闭环/治理"泳道图
- [x] 2.2 为每个阶段补充至少一个具体用户场景实例
- [x] 2.3 识别并记录争议点和未决问题，不混入主流程
- [x] 2.4 产出 Workshop 1 纪要：已对齐内容 + 待解决问题清单

## 3. Workshop 2：对象模型定版

- [x] 3.1 对 thread、run、upload、artifact 逐一讨论定版：业务含义、生命周期状态、关联对象、归属模块
- [x] 3.2 对 knowledge base、report run、closure ticket 逐一讨论定版
- [x] 3.3 明确对象间的主要跳转关系（如 thread→run→artifact→report run）
- [x] 3.4 产出对象模型卡片式清单初稿

## 4. Workshop 3：导航分类与收口

- [x] 4.1 列出工作台当前所有一级导航项
- [x] 4.2 逐一判定每个导航项属于主入口还是扩展域
- [x] 4.3 定义可复用的分类标准，用于未来新增功能/页面的归属判断
- [x] 4.4 整理终版主流程图、对象模型清单、导航分类结论

## 5. 审批与发布

- [x] 5.1 将终版材料发送产品、架构、前后端负责人正式评审
- [x] 5.2 收集评审意见并修改至各方确认
- [x] 5.3 将审批后的主流程图和对象模型清单归档至项目文档库
- [x] 5.4 明确未决问题的 follow-up 时间和负责人，纳入月度评审
