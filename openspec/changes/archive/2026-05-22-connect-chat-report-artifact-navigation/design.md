## Context

DeerFlow 的聊天结果页、报告结果页和产物预览页当前各自独立，页面跳转时缺少来源上下文。用户体验碎片化，无法追踪完整的结果链路。

## Goals / Non-Goals

**Goals:**
- 在聊天结果中嵌入相关报告/产物的直达链接
- 在报告/产物页面提供"回到源 thread/run"的回溯入口
- 每个主链页面都具备来源标识
- 关键跳转链路有可观测标识（如 trace id）

**Non-Goals:**
- 不涉及报告模板和版本追踪（由 ISSUE-07 覆盖）
- 不涉及工单闭环跳转（由 ISSUE-12 覆盖）

## Decisions

### 决策 1：统一跳转参数格式

- **选择**：定义 `CrossPageContext { sourceType, sourceId, threadId, runId }` 统一格式
- **替代方案**：每个跳转自定义参数 → 不可维护
- **理由**：统一格式确保所有跳转可被同一套可观测工具追踪

### 决策 2：所有主链页面携带面包屑来源标识

- **选择**：在页面顶部或面包屑中显示"来自 XX 对话 / XX 报告"的来源标记
- **替代方案**：仅在 URL 参数中携带 → 用户不可见
- **理由**：用户可见的来源标记是消除"死角页面"的关键

## Risks / Trade-offs

- [风险] 循环跳转导致用户迷路 → 面包屑 + 浏览器的后退按钮保持可用
