## Context

认证和租户相关错误是用户最先接触到的系统反馈。当前各服务对这些错误的处理方式不统一，网关、业务服务和前端各有自己的错误码映射，导致同一个问题在不同入口展示不同的错误信息。

## Goals / Non-Goals

**Goals:**
- 统一四类错误：无效令牌(401)、无权限(403)、租户配置问题、上游 auth 不可用(503)
- 所有 API 入口返回一致的状态码和错误码
- 日志记录根因而非表面异常

**Non-Goals:**
- 不改造认证服务本身（如换 OAuth provider）
- 不涉及业务层错误（由 ISSUE-02 覆盖）

## Decisions

### 决策 1：统一错误响应格式

- **选择**：所有入口统一使用 `{ "error": { "code": "AUTH_XXX", "message": "...", "category": "auth|tenant|external" } }` 格式
- **替代方案**：仅用 HTTP 状态码区分 → 无法承载足够的诊断信息
- **理由**：错误码（code）支持客户端精确处理，category 支持日志分类

### 决策 2：网关层负责分类转译，不做根因判断

- **选择**：上游服务返回原始错误码，网关层统一转译为用户可见的错误分类
- **理由**：上游服务不应关心用户展示；网关是统一面

## Risks / Trade-offs

- [风险] 旧客户端依赖旧错误格式 → 保留旧格式一个版本，加 deprecation header
