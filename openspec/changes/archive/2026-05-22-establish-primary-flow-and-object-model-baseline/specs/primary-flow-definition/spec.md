## ADDED Requirements

### Requirement: 主流程图定义主链节点和跳转关系

系统 SHALL 提供一份 Mermaid `flowchart LR` 格式的第一主流程图，覆盖"任务/对话 → 工具/知识 → 报告/产物 → 闭环/治理"的完整链路。

流程图 SHALL 包含以下节点：
- **对话/任务**：thread + run 作为执行入口
- **工具/知识**：skills + MCP + sandbox + knowledge base 作为能力支撑
- **报告/产物**：report run + artifact 作为产出物
- **闭环/治理**：closure ticket 作为结果跟踪

流程图 SHALL 用实线箭头标注主要流向，虚线箭头标注回跳/引用关系。

#### Scenario: 流程图包含完整主链
- **WHEN** 任意角色（产品/架构/开发）阅读主流程图
- **THEN** 可以沿着箭头从"对话/任务"追踪到"闭环/治理"，不出现断链
- **AND** 每个节点的职责在一句话内清晰表述

#### Scenario: 流程图标注跳转关系
- **WHEN** 两个节点之间存在页面或 API 跳转
- **THEN** 流程图中用边连接两个节点，并标注跳转方式（如"页面跳转""API 引用""产物链接"）

### Requirement: 主流程附带节点职责说明

系统 SHALL 为主流程图中每个节点提供一段不超过 3 句话的职责说明，包含：
- 节点是什么（定义）
- 节点为谁服务（目标用户/角色）
- 节点依赖什么（关键前置条件）

#### Scenario: 每个节点有职责说明
- **WHEN** 读者希望理解某个节点的业务含义
- **THEN** 可以在流程图附带的说明表中找到对应的职责描述

### Requirement: 导航分类明确主入口和扩展域

系统 SHALL 将当前工作台一级导航项分类为以下三类：
- **主入口**：直接参与主链的核心页面（聊天、知识库、报告模板、报告运行）
- **扩展域**：辅助主链但不直接参与核心工作流的页面（Agent 管理、技能管理）
- **管理后台**：面向管理员的配置和治理页面（MCP 配置、租户管理）

分类结果 SHALL 以表格形式呈现，包含导航项名称、当前路由、分类、分类理由。

#### Scenario: 导航分类覆盖所有一级入口
- **WHEN** 产品/前端需要确定导航结构
- **THEN** 可以在分类表中找到每个导航项的归属和理由

### Requirement: 未决问题单独列出

系统 SHALL 将主流程定义过程中发现的所有仍未达成共识的问题单独列出，包含：
- 问题描述
- 涉及的对象/模块
- 影响范围
- 建议的解决时机（如 ISSUE-XX）

未决问题 SHALL NOT 混在主流程定义或对象模型定义中，以避免被误认为已达成共识。

#### Scenario: 未决问题不干扰基线
- **WHEN** 读者引用主流程定义作为权威来源
- **THEN** 未决问题不会出现在主流程图或对象模型表中
- **AND** 未决问题在独立章节中清晰可见
