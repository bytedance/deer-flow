## 一、执行摘要

### 1.1 一句话方案

基于 DeerFlow 2.0 构建金融企业级 AI 平台，以 **Harness Engineering** 为核心，通过 **Skill + MCP 二次开发**实现三大场景落地：**ChatBI 智能问数**、**高精度知识库 RAG**、**OCR 智能识别**。

### 1.2 核心价值主张

```
AI 让流程「变短 · 变快 · 变自动 · 变规模化」

变短   ── 人工步骤减少 80%（从 5 步 → 1 步）
变快   ── 响应速度提升 100x+（从小时/天 → 秒级）
变自动 ── 人工介入降低 85%（从 100% → 仅异常复核）
变规模 ── 单实例 50 并发 → 集群 500+ 并发
```

### 1.3 三大场景概览

| 场景 | 核心能力 | 业务价值 | 提效指标 |
|------|---------|---------|---------|
| **ChatBI 智能问数** | 自然语言转 SQL、多轮对话、归因分析、预警报告 | 业务人员自助取数，释放分析师 | 取数时间：4 小时 → **5 秒** |
| **高精度知识库 RAG** | 语义检索、上下文注入、答案溯源、多文档综合 | 精准问答，减少人工查阅文档时间 | 检索准确率：40% → **90%+** |
| **OCR 智能识别** | 表格识别、关键信息抽取、结构化输出、自动比对 | 发票/合同自动处理，释放录入人力 | 处理速度：5 分钟 → **10 秒** |

### 1.4 技术亮点

- **Harness Engineering 平台化**：基于 DeerFlow 2.0 的模块化 Agent 架构，支持 Skill 快速封装业务能力、MCP 无缝集成外部系统
- **全流程自动编排**：Lead Agent + Subagent 多级协作，复杂任务智能拆解并行执行
- **企业级扩展能力**：多租户隔离、水平扩展支持 500+ 并发、全链路审计
- **完全国产化适配**：支持国产数据库（达梦 DM）、国产模型（通义、月之暗面）、内网部署数据不出网

## 二、项目背景与痛点

### 2.1 金融行业 AI 落地现状

| 痛点 | 业务影响 | 根因 |
|------|---------|------|
| 数据获取慢 | 业务人员等待 2-4 小时 | 依赖分析师手工取数 |
| 知识检索不准 | 内部文档散落，搜索结果相关度低 | 关键词匹配，无法理解语义 |
| 手工录入繁琐 | OCR 后需人工核对、修改 | 缺乏端到端自动化 |
| 流程断点多 | 人工在多系统间切换复制粘贴 | 缺乏跨系统编排能力 |
| 并发能力弱 | 高峰期排队等待，响应延迟 | 架构无法弹性扩展 |

### 2.2 为什么要基于 DeerFlow？

传统做法 vs DeerFlow：

```
传统做法：
  ChatBI → 买 SQLBot，商业授权，数据仍需人工理解语境
  RAG    → 买 RAGFlow，无法与其他系统联动
  OCR    → 买商业 OCR SDK，流程仍需人工拼接
  → 多个孤岛系统，集成成本高，维护复杂

DeerFlow 做法：
  统一平台（Harness）→ 编排所有场景
  SQLBot/RAGFlow/商业OCR → 作为专业执行者（通过 MCP 集成）
  → 一个大脑，统一调度，数据互通
```

**DeerFlow 的差异化定位**：

| 外部工具 | DeerFlow 的定位差异 |
|---------|-------------------|
| **SQLBot** | SQLBot 擅长 NL2SQL，但不理解银行业务语境、权限体系、多轮状态。DeerFlow 补全这些 |
| **Dify** | Dify 擅长流程编排，但缺乏多 Agent 协作、复杂推理能力。DeerFlow 负责更高层次的编排 |
| **RAGFlow** | RAGFlow 擅长文档检索，但 DeerFlow 可以把 RAG 结果直接路由给 ChatBI 的指标分析流程 |

> **核心结论**：DeerFlow 不是替代这些工具，而是作为**大脑**让它们协同工作。

### 2.3 比赛主题对齐

| 比赛要求 | 本方案回应 |
|---------|---------|
| AI 工具赋能提效 | ChatBI/RAG/OCR 三大场景全面覆盖 |
| 工作流程优化 | 端到端自动化，人工介入从 5+ 步 → 1 步 |
| 项目开发增速 | Harness Engineering 平台化，Skill/MCP 二次开发快速落地 |
| 贴合工作场景 | 针对银行业务设计：指标体系、权限注入、归因分析 |
| 变短/变快/变自动/变规模化 | 量化指标：取数 2880x 提升，检索 2x 提升，处理 30x 提升 |

## 四、核心能力：Harness Engineering

### 4.1 什么是 Harness Engineering？

Harness Engineering 是 DeerFlow 2.0 的核心设计理念：**将 AI Agent 的能力封装为可复用、可组合、可分发的业务组件**，让开发人员聚焦业务逻辑而非底层实现。

```
传统开发：
  写代码 → 调 API → 处理异常 → 维护迭代

Harness Engineering：
  选 Skill（业务能力包）→ 配置 MCP（外部系统连接）→ 组合流程 → 上线
```

#### 4.5.2 MCP Server 示例：sqlbot-mcp

```python
# mcp/servers/sqlbot_mcp/server.py

from mcp.server import MCPServer
from mcp.types import Tool, CallToolRequest

class SQLBotMCPServer(MCPServer):
    """SQLBot NL2SQL MCP Server"""

    def __init__(self):
        super().__init__("sqlbot-nl2sql")
        self.register_tool(self.nl2sql_tool)

    async def nl2sql_tool(self, request: CallToolRequest) -> dict:
        """
        将自然语言查询转换为 SQL
        """
        query = request.params["query"]
        schema_context = request.params.get("schema_context", {})

        # 调用 SQLBot API
        result = await self.call_sqlbot_api(
            endpoint="/nl2sql",
            payload={
                "query": query,
                "schema_context": schema_context,
            }
        )

        return {
            "sql": result["sql"],
            "confidence": result["confidence"],
            "explanation": result.get("explanation", ""),
        }

    async def call_sqlbot_api(self, endpoint: str, payload: dict) -> dict:
        """调用 SQLBot API"""
        import aiohttp
        async with aiohttp.ClientSession() as session:
            async with session.post(
                f"{SQLBOT_API_URL}{endpoint}",
                json=payload,
                timeout=aiohttp.ClientTimeout(total=30),
            ) as response:
                return await response.json()
```

### 5.6 NL2SQL Router 设计

#### 查询复杂度分类

| 类型 | 判断标准 | 处理方式 |
|------|---------|---------|
| **简单** | 单表 + 单指标 + 无复杂计算 | LLM 直接翻译 SQL |

#### 敏感指标脱敏

```python
SENSITIVE_METRICS = {
    "不良率": {"require_approval": True, "min_level": "分行"},
    "拨备覆盖率": {"require_approval": True, "min_level": "分行"},
    "净利差(NIM)": {"require_approval": True, "min_level": "总行"},
}

def check_metric_access(user_level: str, metric: str) -> dict:
    """检查用户是否有权访问敏感指标"""
    if metric not in SENSITIVE_METRICS:
        return {"accessible": True, "reason": "非敏感指标"}

    required_level = SENSITIVE_METRICS[metric]["min_level"]
    if user_level >= required_level:
        return {"accessible": True}
    else:
        return {
            "accessible": False,
            "reason": f"该指标需要{required_level}级别权限",
            "action": "apply_approval"
        }
```

| **语义层** | 统一的指标/标签定义层，确保口径一致 |
| **Code Agent** | 通过执行代码完成复杂业务逻辑 |
| **T+1** | 数据延迟一天，如当日查昨日的数据 |
| **MCP** | Model Context Protocol，标准化连接外部系统的协议 |
