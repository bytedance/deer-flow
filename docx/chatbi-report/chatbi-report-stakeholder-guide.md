# 【完整提纲】SQLBot 报表自动化生成方案（v2）

> **目标读者**：报表设计人员、业务部门同事、项目干系人
> **文档版本**：v2（2026-06-22 重大重构）
> **文档用途**：让大家理解 DeerFlow 是怎么把一份带中文指标的 Markdown 样例表，自动变成正式报表（JSON + 回填 Markdown + Word 文档）的

---

## 一、为什么要做这件事？

### 1.1 现状的痛点
- 报表设计人员每周要交 5 章节 × 5 张报表 = 25 张报表
- 每张报表平均 6 个中文指标
- 每个中文指标都要人工去 SQLBot 指标库里查对应的英文代码
- **总工作量：150 次/周 手工查表 + 手工写 JSON + 手工排版 Word**
- 容易出错、无法复用、人力浪费严重

### 1.2 我们想达到的目标
让 AI 自动完成：
- ✅ 中文指标 → 英文代码的智能匹配
- ✅ 自动生成结构化的 JSON 数据
- ✅ 自动回填 Markdown（中文显示 + 英文代码作为副标）
- ✅ 自动生成排版精美的 Word 文档
- ✅ 遇到 AI 拿不准的指标，**精准问人**，而不是全错或全跳过

### 1.3 一句话总结
> **以前要人手工查 150 次，现在 AI 查，遇到拿不准的再精准问你一次。**

### 1.4 v2 相对 v1 的关键变化（重要！）

| 维度 | v1（旧方案） | v2（新方案） | 业务影响 |
|------|-------------|-------------|---------|
| **执行主体** | AI 主管家 + AI 小助手（两层） | AI 主管家独立完成 | 流程更简洁、调试更容易 |
| **L3 澄清** | 让小助手问你（**实际问不出来**） | 主管家亲自问你 | L3 真的能打断成功 |
| **中途退出** | 需要手写存档文件 | 系统自带自动存档 | 退出再回来能继续干 |
| **重复匹配** | 每次都重新问 AI | 自动记忆已匹配的指标 | 同会话更快、更省 |
| **AI 编造指标** | 可能把不存在的指标混进结果 | 自动识别并拒绝编造 | JSON 干净可信 |
| **Word 描述语言** | 中文/英文可能混用 | **Word 默认显示中文** | 报表受众是中国用户，不再别扭 |

### 2.2 用生活化的类比理解这三层
| 层级 | v1 类比（旧） | v2 类比（新） |
|------|--------------|--------------|
| 第 1 层 技能入口 | 公司前台 / 总机 | 公司前台 / 总机 |
| 第 2 层 执行层 | 财务部专员小李（独立房间） | 你的直属老板（lead agent，平时也在忙其他事） |
| 第 3 层 交付物 | 小李做完交给你的文件夹 | 老板做完直接交付的文件夹 |

### 2.3 为什么砍掉"小李"？讲给非技术人听
v1 让 AI 主管家把活派给一个"AI 小助手"独立干，本意是想让主管家不被干扰。但实测发现两个问题：
1. **"小助手"问不出问题**：当 AI 拿不准要问你时，"小助手"问不出来（机制有 bug），导致 L3 澄清功能其实是空壳
2. **DeerFlow 系统自带"小助手"的能力**：自动存档、自动总结压缩，这些原本想用"小助手"解决的问题，系统已经做掉了

所以 v2 让主管家直接干活的方案更简单、更可靠。

## 三、报表设计人员要做什么？（最关键的一节）

### 3.1 你只需要做一件事：写一份"带标记的 Markdown 报表样例"

### 3.2 Markdown 样例长什么样？

```yaml
# 标题行
# 2026 年第二季度经营分析报告

## 章节: 财务表现
  (一个章节 = 一组相关报表)

### 报表: 季度营收对比
> 描述: 用表格展示本季度营业收入、营业成本、毛利的同比和环比数据
  (一段中文提示词，AI 会基于此生成英文描述)

<table>
  <thead>
    <tr>
      <th rowspan="2">季度</th>
      <th colspan="2">财务指标</th>      ← 这是"复合表头"
      <th colspan="2">增长率</th>
    </tr>
    <tr>
      <th>{{营业收入}}</th>              ← {{}} 包起来的才是要映射的指标
      <th>{{营业成本}}</th>
      <th>{{环比增长率}}</th>
      <th>{{同比增长率}}</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>2026 Q2</td>
      <td>1580</td>                       ← 数据值，不需要映射
      <td>980</td>
      <td>9.0%</td>
      <td>15.2%</td>
    </tr>
  </tbody>
</table>
```

### 3.3 三条铁律（必须遵守）
| # | 规则 | 为什么 |
|---|------|--------|
| 1 | 中文指标必须用 `{{}}` 包裹 | 系统靠这识别哪些要查 |
| 2 | 表格必须用 **HTML 表格**（`<table>`），不能用 Markdown 表格 | HTML 才能合并单元格、支持多级表头 |
| 3 | 每个报表必须有"描述"段落（`> 描述: ...`） | AI 据此生成英文版描述（Word 文档默认显示中文原文） |

### 3.4 写之前会自动检查（系统帮你把关）
系统会用 `md_lint.py` 自动检查你的样例：
- ❌ `{{}}` 没成对 → 报错并指出哪行
- ❌ HTML 表格没闭合 → 报错并指出哪行
- ❌ 章节里没报表 → 报错
- ⚠️ 指标名超过 8 个汉字 → 警告
- ⚠️ 同一指标在多张表里写法不统一 → 警告

## 四、AI 自动匹配的三个层次（L1 / L2 / L3）

> 这是这套方案最聪明的部分：**逐层升级、精准打断**。

### 4.1 L1 精确匹配（自动搞定）
- 中文名完全等于 SQLBot 里的某个指标名
- 比如 "营业收入" → `revenue`
- **不需要人工干预，100% 自动**
- **v2 新增**：命中后自动进入"指标缓存"，下次同指标直接用，不重复查

### 4.2 L2 模糊匹配（LLM 智能选择）
- 中文名不完全等于，但 AI 根据语义选最接近的
- 比如 "环比增长率" → `qoq_growth`（置信度 0.85）
- **置信度 ≥ 0.6** 就自动采用
- **置信度 < 0.6** 进入 L3
- **v2 新增**：单次调用批量处理多个指标（避免 30 次串行慢调用）
- **v2 新增**：幻觉校验 —— AI 编造 SQLBot 里不存在的代码会自动拒绝

### 4.3 L3 人工澄清（精准打断）
触发条件：**前 2 名候选差距 ≤ 0.1**（AI 自己都拿不准）

这时 AI 主管家会亲自停下来问你：

> 📢 **AI 提问**：「指标 `{{增长率}}` 在 SQLBot 里有 3 个候选：
> 1. `yoy_growth`（同比增长率）
> 2. `qoq_growth`（环比增长率）
> 3. `mom_growth`（环比增长率 v2）
>
> 你想要哪一个？」

你可以选 1 个，或者直接说"跳过"。

> ⚠️ **v2 重要变化**：v1 时 AI 想问你会"问不出来"（机制有 bug），v2 已经修复，**L3 真的能打断成功**。

### 4.4 三层匹配汇总

| 层级 | 触发条件 | 是否需要人 | 典型场景 |
|------|---------|-----------|---------|
| L1 | 中文名完全匹配 | 否 | "营业收入" → `revenue` |
| L2 | 模糊但置信度 ≥ 0.6 | 否 | "环比增长率" → `qoq_growth` |
| L3 | 置信度 < 0.6 且差距小 | **是** | "增长率" 多种含义需要你定 |

## 五、10 步流水线（AI 的工作清单）

> 报表设计人员不需要懂技术细节，但理解这 10 步有助于你理解"为什么有时快、有时慢"。

```
[1] 读取你上传的 Markdown 文件
       ↓
[2] 格式校验（md_lint.py 检查）
       ↓ 出错就中断
[3] 解析成内存里的结构化对象（AST）
       ↓
[4] 收集所有 {{指标}} 标记，去重
       ↓
[5] 批量查 SQLBot 指标库（已查过的会命中缓存，跳过）
       ↓ 网络失败就重试 3 次
[6] L1 精确匹配
       ↓ 没匹配上的进入下一步
[7] L2 模糊匹配（LLM 批量选 top-1，含幻觉校验）
       ↓ 拿不准的进入下一步
[8] L3 人工澄清（主管家亲自问你，回答后自动恢复）
       ↓
[9] LLM 生成英文描述（中文描述保留）
       ↓
[10] 输出三件套：JSON + Markdown + Word
```

### 5.1 关键步骤拆解（业务语言版）

| 步骤 | 业务说法 | 需要你做什么 |
|------|---------|-------------|
| [1] 读取 | 把你的样例加载进来 | 已经做完 |
| [2] 校验 | 检查格式有没有错 | 错了会告诉你改哪行 |
| [3] 解析 | 把样例变成结构化数据 | 无 |
| [4] 收集 | 列出所有要查的指标 | 无 |
| [5] 查库 | 去 SQLBot 找候选 | 网络失败会自动重试 |
| [6] L1 精确匹配 | 中文名完全一致的直接对上 | 无（100% 自动）|
| [7] L2 模糊匹配 | 拿不准的让 AI 选最接近的 | 无（如果置信度高）|
| [8] L3 澄清 | AI 拿不准时问你 | **回答问题**（约 30 秒）|
| [9] 翻译 | AI 把中文描述翻译成英文版（JSON 用）| 无 |
| [10] 渲染 | 生成 JSON + Markdown + Word | 无 |

## 六、你会拿到什么？（交付物三件套）

### 6.1 件套 1：结构化 JSON（`report.json`）
- 用于二次处理、数据回填、Phase 2 数据查询
- 完整保留所有指标的映射关系（中文名 + 英文代码 + 置信度 + 匹配方式）
- **v2 新增字段**：
  - `data_type`：决定 Word 数字格式（千分位 / 百分比 / 货币 / 比率）
  - `display_format`：精细控制显示样式（如 `#,##0.00` 或 `0.0%`）
  - `time_dimension`：表达"本月/YTD/季度累计"等时间维度
  - `data_source`：数据来源标记（Phase 2 用）
  - `last_updated` / `version`：指标版本管理
- **v2 新增监控指标**：
  - `metadata.cache_hits`：缓存命中次数
  - `metadata.llm_calls`：LLM 调用次数（含批量）
  - `metadata.duration_seconds`：耗时

### 6.2 件套 2：回填 Markdown（`report.md`）
- 中文显示 + 英文代码作为副标
- 例：`{{营业收入}}` 变成 `营业收入 (\`revenue\`)`
- 未匹配项会自动标 ⚠️UNMAPPED，便于人眼检查

### 6.3 件套 3：Word 文档（`report.docx`）
- **v2 关键修复**：Word 默认显示中文描述（`description.zh`），不再中英混用
- 排版精美：多级标题、合并单元格、表头底色
- 字体：微软雅黑（标题）/ 宋体（正文）
- 横向排版，预留 2cm 边距
- **v2 新增**：数字格式根据 `data_type` 自动应用（千分位 / 百分比 / 货币）
- 可直接在 Word / WPS 中打开使用

### 6.4 额外两个辅助文件
| 文件 | 作用 |
|------|------|
| `report.match.log` | 决策日志：每个指标是怎么匹配的、置信度多少、什么时候问了人、什么时候拒绝了幻觉 |
| `report.status.json` | 状态报告：成功 / 部分成功 / 失败 + 失败原因 + 缓存命中数 + LLM 调用数 |

## 七、出了错怎么办？（11 类失败的对应处理）

> ⚠️ **v2 重要变化**：F10 和 F11 含义已变。F10 不再是"超时"，F11 不再是"max_turns 用完"。

| 编号 | 出了啥事 | 系统怎么处理 | 你需要做什么 |
|------|---------|-------------|-------------|
| F1 | 你写的 Markdown 格式错 | AI 中断任务，告诉你哪行错了 | 修改 Markdown 重新提交 |
| F2 | SQLBot 配置缺失（API key 没配） | AI 中断任务 | 联系运维配环境变量 |
| F3 | SQLBot 服务器宕机 / 超时 | 自动重试 3 次（1s/2s/4s），还失败就中断 | 等服务恢复后重跑 |
| F4 | 某个指标在 SQLBot 里完全没有 | 标记为 `unmatched`，**不影响其他指标继续** | 手动补这个指标，或用近似指标 |
| F5 | L2 模糊匹配置信度低，但只有 1 个候选 | 用 top-1，标记为 `low_confidence` | 检查映射是否合理 |
| F6 | L2 置信度低 + 多个候选差距小 | **触发 L3 问你** | 回答问题即可 |
| F7 | L3 问你时你选择"跳过" | 标记为 `user_skipped`，继续下一个 | 无 |
| F8 | LLM 翻译描述失败 | 重试 1 次，还失败则保留中文 + 标 `[TRANSLATION_FAILED]` | 后续人工润色 |
| **F10** ⚠️ | **LLM 编造了 SQLBot 里不存在的代码** | **拒绝该结果，回退重试；仍失败 → 进 L3** | **如果进了 L3 需要回答问题** |
| **F11** ⚠️ | **AI 处理太多指标导致上下文太长** | **SummarizationMiddleware 自动总结老消息** | **完全无需处理（系统自动搞定）** |
| F9 | Word 渲染失败 | 返回 JSON 和日志，标记 `render_error` | 手动执行 `render_docx.py` 重跑 |

> 📌 **v2 移除**：v1 的 F10（subagent 超时）和 F11（max_turns 用完）已不存在，因为 v2 砍掉了 subagent + 用系统自带的总结和存档机制。

### 7.1 三种最终状态

| 状态 | 含义 | 系统怎么告诉你 |
|------|------|---------------|
| ✅ success | 全部指标都匹配上了 | 给你看三件套 |
| ⚠️ partial | 部分匹配上了 | 给你看三件套 + 列出没匹配上的指标清单 |
| ❌ error | 整个任务失败 | 不给三件套，告诉你失败原因和检查清单 |

### 7.2 v2 新增"幻觉校验"是什么意思？

AI 在做 L2 模糊匹配时，可能"自作聪明"地编造一个 SQLBot 里根本不存在的英文代码。比如你写 `{{客户数}}`，SQLBot 里没有这个指标，AI 可能编一个 `customer_count`（听起来合理但 SQLBot 里没有）。

**v2 解决方案**：每次 LLM 返回结果后，系统强制校验 —— 返回的代码必须在 SQLBot 候选列表里。如果不在：
1. 拒绝这个结果
2. 在决策日志（match.log）里写"hallucination rejected"
3. 自动回退重试
4. 还不行就进入 L3 问你

这样保证最终 JSON 里不会出现 SQLBot 里不存在的"幽灵指标"。

## 八、报表设计人员的完整协作流程

### 8.1 一次报表生成的全流程时间线（v2 简化版）

```
T+0min   你：上传 Markdown 样例到 DeerFlow
T+1min   AI 主管家：识别到是 chatbi-report 任务，加载 SKILL.md
T+2min   AI 主管家：格式校验、解析结构
T+3min   AI 主管家：批量查 SQLBot 指标库（已查过的命中缓存，快）
T+5min   AI 主管家：L1 精确匹配（80% 的指标在这里搞定）
T+8min   AI 主管家：L2 模糊匹配（再搞定 15%，批量处理）
T+10min  AI 主管家：如果有 L3，向你提问  ← 你需要响应
T+12min  你：回答 L3 问题（或选"跳过"）
T+13min  AI 主管家：生成英文描述、渲染 Word
T+15min  AI 主管家：交付三件套
```

> 📌 **v2 变化**：少了 v1 的"主 AI 派单给小助手 → 小助手开工"的两个环节，直接由主管家一气呵成。

### 8.2 你的参与时刻
90% 的情况下你只需要：
1. 上传 Markdown 样例
2. 等 15 分钟
3. 下载三件套

10% 的情况下你需要：
- 响应 L3 提问（每个问题约 30 秒）

### 8.3 v2 新增的"中途退出也不怕"能力（v1 没有！）

**v1**：如果你中途关掉 DeerFlow，下次回来要从头开始。
**v2**：系统自动存档你跑到的每一步，下次回来同一对话直接接着干，不用重跑。

具体操作：再次打开同一个工单对话，AI 会说"上次跑到了 step 7，我从这里继续"。

## 十、给报表设计人员的 10 条小贴士

> 这些都是从失败案例里总结出来的"避坑指南"。**前 5 条是 v2 新增或强化的**。

1. ⚠️ **指标名尽量简洁**（≤8 个汉字），太长的短语匹配率低
2. ⚠️ **同一概念在不同表里写法要统一**（别一会儿"营收"一会儿"营业收入"）
3. ⚠️ **多级表头必须用 HTML**（`<th rowspan>`、`<th colspan>`），Markdown 表格不支持合并
4. ⚠️ **每个报表都写中文描述段落**，Word 默认显示这段中文
5. ⚠️ **数据值用真实数字（如 `1580`、`9.0%`）**，v2 会根据指标类型自动加千分位/百分比格式
6. 章节标题前用 `## `，报表标题前用 `### `，层级要清晰
7. 不要在 `{{}}` 里加英文括号或备注，要纯中文名
8. 未匹配项不会让任务失败，放心尝试新指标
9. **v2 新增**：决策日志（match.log）一定看一眼，那里记录了"幻觉校验拒绝"的指标
10. **v2 新增**：中途退出别慌，下次回来同一对话能接着跑
