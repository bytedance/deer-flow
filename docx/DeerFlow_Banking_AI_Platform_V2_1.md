## 一、执行摘要

### 1.1 一句话方案

**以 DeerFlow 2.0 为内核，二次开发为金融企业级 AI Agent 平台，三大场景（ChatBI / RAG / OCR）作为 Skill 层统一运行在同一个框架下。**

### 1.2 核心价值主张

```
AI 让流程「变短 · 变快 · 变自动 · 变规模化」

变短   ── 人工步骤减少 80%（从 5 步 → 1 步）
变快   ── 响应速度提升 100x+（从小时/天 → 秒级）
变自动 ── 人工介入降低 85%（从 100% → 仅异常复核）
变规模 ── 单实例 50 并发 → 集群 500+ 并发
```

### 1.3 三大场景定位

| 场景 | 在框架中的角色 | 核心价值 |
|------|--------------|---------|
| **ChatBI** | Skill: `banking-chatbi` | 自然语言问数，释放分析师 |
| **RAG 知识库** | Skill: `banking-rag` | 精准问答，减少人工查阅 |
| **OCR 识别** | Skill: `banking-ocr` | 文档自动处理，释放录入人力 |

> **关键设计**：三个场景不是三个独立系统，而是同一个 Agent 框架下的三个 Skill，业务人员按需调用。

## 三、核心能力：Harness Engineering

### 3.1 什么是 Harness Engineering？

**Harness = 驾驭系统，让开发人员聚焦业务而非底层**

```
传统开发模式：
  写代码 → 调 API → 处理异常 → 维护迭代 → 新场景重新写

Harness Engineering 模式：
  选 Skill（业务能力包）→ 配置 MCP（外部连接）→ 组合流程 → 上线
```

### 5.3 Skill 详解

#### 5.3.1 banking-chatbi

```yaml
# banking-chatbi/SKILL.md
---
name: banking-chatbi
description: 银行 ChatBI 技能 — 自然语言问数、归因分析、报告生成
version: 1.0.0
metadata:
  deerflow:
    tags: [banking, chatbi, nl2sql]
    requires_tools: [sql_agent, metric_center, permission_injector]
    subagents: [sql_subagent, insight_subagent, report_subagent]
---

# 银行 ChatBI 技能

## 能力矩阵

| 能力 | 说明 | 调用方式 |
|------|------|---------|
| NL2SQL 查询 | 自然语言转 SQL | `sql_agent.nl2sql()` |
| 归因分析 | 指标异动原因分析 | `insight_subagent.attribute()` |
| 报告生成 | 自动生成分析报告 | `report_subagent.generate()` |

## 查询流程

1. **意图识别**
   - SIMPLE_SQL：单表单指标 → LLM 直译
   - COMPLEX_SQL：多表多指标 → SQLBot
   - ATTRIBUTION：归因分析 → Insight Agent
   - REPORT：报告生成 → Report Agent

2. **权限注入**
   - 根据用户行员号注入可访问机构
   - 敏感指标触发审批流程

3. **结果验证**
   - 空结果检测
   - 业务逻辑校验
   - 异常时触发 Self-Correction
```

```yaml
# 银行 RAG 技能

## 能力矩阵

| 能力 | 说明 | 调用方式 |
|------|------|---------|
| 语义检索 | 理解金融术语，精准匹配 | `vector_db.search()` |
| 混合检索 | 向量 + 关键词双重召回 | `hybrid_search()` |
| 答案溯源 | 每条结论标注来源 | `context_assembler.trace()` |
| 多文档综合 | 跨文档整合信息 | `llm.synthesize()` |

## 检索流程

1. **Query Rewrite**
   - 同义词扩展
   - 金融术语规范化

2. **检索阶段**
   - 向量相似度检索（Top-K）
   - 关键词 BM25 检索
   - 结果合并去重

3. **重排序**
   - Cross-Encoder 重排序
   - 相关性阈值过滤

4. **答案生成**
   - 上下文组装
   - LLM 生成答案
   - 来源标注
```

```yaml
| 结构化输出 | JSON / 自动填表 | `formatter.structured_output()` |
| 异常检测 | 金额异常/重复检测 | `anomaly_detector.check()` |

## 处理流程

1. **图像预处理**
   - 倾斜矫正
   - 去噪增强
   - 表格区域定位

2. **OCR 识别**
   - 文字识别（印刷体/手写体）
   - 表格结构识别

   - 字段标准化

4. **异常检测**
   - 金额异常检测
   - 重复报销检测
   - 供应商一致性校验

5. **输出**
   - 正常单据 → 自动入库
   - 异常单据 → 人工复核
```

### 6.2 与外部工具的分工

| 外部工具 | DeerFlow 的定位 | 各自职责 |
|---------|----------------|---------|
| **SQLBot** | 编排者 + 上下文补全 | SQLBot: NL2SQL 核心能力<br>DeerFlow: 业务语境理解、权限注入、多轮状态 |
| **Dify** | 流程执行者 | Dify: 表单处理、审批流程<br>DeerFlow: 高层次任务规划、跨系统联动 |
| **RAGFlow** | 检索执行者 | RAGFlow: 文档解析、向量索引、语义检索<br>DeerFlow: 检索结果路由、与 ChatBI 联动 |

### 6.3 集成优势

```
DeerFlow 作为「编排大脑」的价值：

1. 统一入口 ── 用户只需和一个平台交互，背后自动调度多个专业系统
2. 上下文共享 ── 三个场景的数据互通，避免信息孤岛
3. 流程编排 ── 复杂任务（如「分析报告」需先 RAG 再 ChatBI）自动串联
4. 统一审计 ── 全链路操作日志，便于合规审计
```
