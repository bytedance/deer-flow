# 第一章 知识库概述

知识库系统旨在将非结构化文档转化为可检索、可推理的结构化知识资产。在典型的企业场景中，产品手册、技术白皮书、会议纪要、设计文档散落在各个角落，员工难以快速定位所需信息，更无法基于这些信息进行跨文档的关联分析。本系统通过离线索引流水线，将上传的文档统一解析为 Markdown 文本，再按照标题层级切分为语义完整的切片，并在此基础上构建向量索引、知识图谱与百科条目三条检索路径。向量索引负责事实细节的精确召回，知识图谱负责实体关系的结构导航，百科条目负责概念主题的深度综述。三条路径各司其职又相互补充，共同支撑上层智能体的问答与调研能力。本节余下部分介绍系统的整体目标与边界条件，为后续章节的设计展开奠定基础。索引过程是异步的：文档上传后进入后台流水线，依次完成解析、切片、向量化、图谱抽取与百科生成，每个阶段的状态都会持久化到业务数据库，支持断点续跑与失败重试，确保大规模语料场景下的鲁棒性。

## 1.2 大规模语料处理

当知识库规模增长到万级文档时，索引流水线必须面对成本与时延的双重压力。以一份典型的两百页技术白皮书为例，解析阶段会产出数百个切片，每个切片都需要进行向量化与图谱抽取调用。如果缺乏有效的并发控制与限流策略，突发的大量上传请求会瞬间打满模型服务商的速率配额，导致大面积失败。因此系统在设计之初就将速率整形作为一等公民：向量化调用按批次打包，图谱抽取调用按每秒请求数限流，工作器按文档粒度控制并发上限。这些参数均可通过配置调节，以适应不同服务商的配额约束。

除了速率压力，长文档还带来上下文窗口的挑战。某些章节的正文可能长达数千词元，远超检索切片的目标尺寸。系统采用结构感知为主、大小约束兜底的切片策略：优先按照标题层级切分，保证每个切片语义完整；对超长块按段落递归细分；对过小的块与相邻块合并，避免碎片化检索结果。每个切片都记录标题路径、页码与词元数等元数据，供检索结果引用与前端预览使用。

失败处理同样不可忽视。文档解析可能因为文件损坏而失败，图谱抽取可能因为模型输出格式异常而失败，向量化可能因为网络抖动而失败。系统为每个阶段设计了独立的失败语义：解析失败直接标记文档失败并记录原因；抽取失败仅标记对应切片，支持断点续跑；向量化失败按切片粒度重试。单文档的图谱抽取失败率超过阈值时，系统会标记该文档的图谱路径降级，前端明确提示用户，杜绝静默的不完整索引。

监控与可观测性也是大规模场景的基本要求。索引流水线的每个阶段都会输出结构化日志与指标：文档状态迁移、切片级抽取成功率、向量化耗时分布、百科生成触发次数等。运维人员可以通过这些信号快速定位瓶颈，例如当抽取失败率突增时，通常意味着模型侧的输出格式发生了漂移，需要及时调整提示词或升级解析逻辑。前端的管理界面也会消费这些状态，向用户展示每个文档的实时进度与失败原因，避免用户在长时间的索引过程中失去耐心。

最后，成本核算贯穿整个流水线设计。向量化调用按输入词元计费，图谱抽取是最昂贵的环节，百科生成则只在触发时产生费用。系统会在索引完成后记录本次语料的调用量与词元消耗，帮助管理员校准限流参数与预算配额。对于超大规模的知识库，管理员还可以选择先索引核心文档子集，验证检索质量后再全量推送，从而把试错成本控制在可接受的范围内。

# 第二章 检索架构

在线查询阶段，系统为智能体提供三个检索工具。混合检索工具面向事实细节类问题，先将查询改写为稠密与稀疏两路向量，在向量库中分别预取候选，融合排序后再经精排模型输出最终结果。图谱检索工具面向关系型问题，先识别查询中的实体，再在图谱中做一到两跳的关系扩展，最后按来源切片取回正文。百科检索工具面向概念综述类问题，直接在百科条目库中做向量匹配，取回预先生成的条目全文。三个工具的返回都携带引用元数据，供智能体在回答中标注来源。
