# Tool artifact middleware

## Resolution

*(optional, if `tool_artifacts.enabled && tool_artifacts.resolve_handles_in_args`, default on)* Resolves `art_xxxxxxxx` artifact handles found in tool-call arguments to their real references (`ThreadState.tool_artifacts[].real_ref`) before the tool executes (issue #4676). Runs inner of ToolProgressMiddleware and outer of ToolErrorHandlingMiddleware; mutates only the request args, never the message history. Handles may appear bare, inside backticks, or nested in dict/list args; unknown handles are left untouched. Both config flags must be on — disabling `tool_artifacts.enabled` stops resolution for threads that still carry registry state.

## Capture

*(optional, if `tool_artifacts.enabled`, default on)* Captures lightweight artifact references from tool results into `ThreadState.tool_artifacts` (a reducer channel, so entries survive summarization compaction). `tool_artifacts.enabled` gates the whole middleware (capture and consumption tracking); when off, `before_model` returns nothing regardless of registry state. Runs as a `before_model` hook (never wraps a `ToolMessage` in a `Command`), rescans tool messages on every model call while skipping results already processed (a bounded FIFO records every extraction, successes included — this is what keeps sliding-window evictions final instead of resurrecting evicted entries whose ToolMessage is still in context) and settled tool-call args (a second bounded FIFO; a call settles only after every referenced handle resolved against the effective registry — state entries plus anything captured in the same before_model call — so a transient miss retries rather than permanently losing the consumption mark), and returns a state update; it also tracks which handles were consumed by later tool calls (handle found in a subsequent AIMessage's args) so the model-context projection can mark entries `[consumed]`; when both fire in one call their lists are concatenated, never dict-merged (dict-merging dropped one side's entries). Position-independent in the tool-execution wrap chain: it is a `before_model` hook reading state messages, so it sees the normalized results stored in state regardless of its wrap position (error results are skipped at extraction via `status == "error"`); it is appended after ToolErrorHandlingMiddleware for readability only. Handles are `art_` + 8 hex chars derived deterministically from (thread_id, tool_call_id, call_index, per-result ordinal), so multiple references inside one result never collide. Extraction combines all of: structured-content string values under known keys (`file`/`path`/`url`/`task_id`/...) as concrete refs (unknown payloads fall back to one untruncated JSON `data` entry), `file`/`image` content blocks with http(s)/path-shaped URL sources (`data:`/`blob:` URIs are rejected so embedded-resource payloads never enter state or tool args), and conservative free-text scanning of both text blocks and plain-string results such as built-in sandbox tool output (sandbox paths + remote file URLs, gated by `detect_refs_in_text`). The reducer enforces only an absolute ceiling (1000); the configured `tool_artifacts.max_entries` is a per-agent sliding retention window: when a capture round would exceed it, the middleware appends a trailing `{"op": "trim_to", "keep": N}` directive and the reducer evicts the oldest entries (fresh captures are always registered — nothing freezes at the cap), so agents with different configs in one process do not share a cap. Entries carry only metadata (path/URL, name, type, mime), never full content.

## Durable projection

Artifact handles are projected with working notes and summary history in the hidden HumanMessage data block when `tool_artifacts.enabled` and `inject_model_context` are enabled. Values remain untrusted data. Artifact capture precedes compaction; task continuity and PII redaction retain independent configuration. `inject_tool_artifacts` participates in the middleware release policy fingerprint.
