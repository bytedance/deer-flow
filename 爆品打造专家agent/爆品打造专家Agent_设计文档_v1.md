# 爆品打造专家 Agent · 设计文档（v1 · 第一阶段）

> **版本**：v1.0 — 第一阶段：信息中转 + AI 初步归因
> **定位**：运营副驾 v1——不是替运营决策，而是把分散在各系统的数据实时拉通、分级预警、给出 AI 初步归因，让运营"及时洞察、一眼看全"
> **时间窗口**：2 周交付试点版本（1 个站点、20–30 个 S/A 级 ASIN）
> **核心节奏**：每日定时扫描 + 对话主动触发；不做升级、不做动作建议直推、不做 Web 面板
> **数据原则**：不存数据，全部通过 MCP 工具实时调用；仅做内存级 TTL 缓存防限频

---

## 一、定位与核心原则

### 1.1 要解决的问题

| 痛点 | 现状 | 后果 |
|------|------|------|
| 响应延迟 | 运营不会每天看所有链接，评分暴跌、库存断货、排名下滑发现太晚 | 问题已造成实质影响才处理 |
| 精力分散 | 需跨领星、插件、后台多个页面手动比对数据 | 大量重复劳动、长尾链接被忽视 |
| 转化链路断裂 | 站外热词外溢到亚马逊（如"拿铁味香水"百万搜索）站内无人承接 | 高搜索低转化 |
| 缺乏过程追踪 | 月度复盘才看结果，推广动作是否执行没有实时追踪 | 错过挽回窗口 |

### 1.2 第一阶段边界（KP 会议共识）

**第一阶段做什么**：信息中转 + 分级预警 + AI 初步归因。核心是"把所有链接的情况给你"，把分散在领星、插件、后台的数据实时整合到飞书统一视图。

**第一阶段不做什么**：
- 不直接给优化动作建议（建议能力在影子模式下后台跑，存底不推送）
- 不做"未响应自动升级"机制
- 不让 AI 替人决策；高等级异常强制人工介入
- 不做 Web 面板/BI 看板

### 1.3 六条核心设计原则

1. **全面可视优先**：第一步是"让运营一眼看到所有链接状态"，不是"告诉运营做什么"
2. **判断—执行—应对三标准闭环**：每个异常有明确判定标准（阈值）、执行归属（谁处理）、应对路径
3. **高等级异常人决策**：紧急异常强制人工介入，AI 只做数据聚合与初步归因
4. **指标来自真实使用场景**：拒绝"看起来有用但不用"的虚设指标
5. **先让大家用起来**：第一版不追求完美，跑通链路、运营每天看一眼、逐步迭代
6. **阈值外也要留痕**：未达阈值但有明显波动的指标也记录到多维表，供回溯分析，避免漏报

### 2.2 两种触发方式

**① 每日定时任务**
- 每天 9:00 扫一遍所有 S/A 级链接
- 调 MCP 拉数据 → 规则判定 → LLM 归因 → 按等级推送（紧急即使是 9 点扫出也单独即时推）
- 所有结果（含未达阈值的波动）写多维表

**② 对话主动触发**
- 运营在飞书 @机器人或进对话直接问："看下 ASIN 127061 最近怎么样"、"为什么 UK 站流量掉了"
- Agent 实时调 MCP 拉数 → 同一条规则+归因链路 → 在对话里直接返回答复
- 支持多轮追问："那广告呢？"、"对比下竞品 xxx"
- 对话只读：第一阶段不做"帮我改标题""帮我调价"这类执行动作

### 2.3 核心组件职责

| 组件 | 职责 |
|------|------|
| MCP 工具层 | 20 个工具分 4 Server；不存数据，内存 TTL 缓存防限频 |
| 定时调度器 | 每日 9:00 触发全量扫描 S/A 级链接 |
| 对话入口 | 飞书机器人接消息 → Agent 按需拉数 → 自然语言答复 |
| 规则引擎 | 三级阈值判定 + 波动留痕 |
| LLM 归因 | 结构化证据 → 自然语言归因说明 + 影子建议 |
| 飞书机器人 | 三档卡片推送 + 对话回复 |
| 多维表 | 异常告警表 + 波动留痕表 + 影子建议表（统一视图） |

## 四、异常分级与触发规则

### 4.1 三级预警定义

| 等级 | 颜色 | 触达方式 | 运营感知 |
|------|------|---------|---------|
| 🔴 紧急 | 红 | 飞书即时消息 @对应运营 + 群内高亮 | 必须当天看 |
| 🟡 警告 | 黄 | 飞书普通卡片推送 | 当天内处理 |
| 🔵 信息 | 蓝 | 每日 9:00 汇总成一条日报卡片 | 例行查看 |

### 4.2 异常场景 × 分级映射（v0 阈值，签字后运行中校准）

| 异常场景 | 主判定指标 | 🔴 紧急 | 🟡 警告 | 🔵 信息 | 佐证交叉 |
|---------|----------|---------|---------|---------|---------|
| 销量/达成骤降 | 周环比/同比销量 | 下降 >35% | 下降 20–35% | 下降 10–20%（留痕） | Sessions、CVR、排名 |
| 断货风险 | 库存可售天数 | 可售 <30 天 + Sessions↑ | 可售 <45 天 | 可售 <4 个月（欧 5 个月） | 在途、近 7 天日均销 |
| 差评冲击 | 新增差评 / 评分 | 单日差评 ≥N / 星级↓≥0.3 | 星级↓ 0.1–0.3 | 评分缓慢下滑 | CVR、退货率 |
| Listing 异常 | 链接状态 | 不可售/下架/购物车丢失 | — | — | — |
| 广告效率恶化 | 父ASIN ACOS | 环比 +50% 或超基准 1.5 倍 | 环比 +20–50% | 环比 +10–20% | ROAS、活动 CVR、花费占比 |
| 关键词排名丢失 | 核心词广告/自然位 | Top10 词掉出 Top30 | Top10 词掉 5 名+ | 流量占比小幅下滑 | Sessions、广告位 |
| 热词未承接 | 搜索热度排名 vs 自然/广告位 | — | 热度进 Top50 但排名未进 Top50 | 热度上升但未埋词 | Sessions、CVR |
| 竞品抢量 | 竞品销量/价格 | 竞品降价 ≥20% 且自身转化↓ | 竞品销量↑+自身流量↓ | 竞品小幅变动 | 价格、关键词占比 |
| 退货率异常 | 退货率 | — | 环比 +X pp 或超基准 | 小幅上升 | 评分、CVR |
| 冗余库存 | 库龄/冗余成本 | 库龄 ≥270 天 | 库龄 180–270 天 | 库龄 90–180 天（留痕） | 近 30 天销量 |
| 配送成本 | 配送费 | — | 环比 +20% 或超基准 | 小幅波动 | ACOAS、毛利 |
| 毛利异常 | 毛利率（BMB，v1.1） | 毛利率 < 安全线 | 环比下滑显著 | 小幅波动 | 配送费、ACOS |

表中 X、N 等具体阈值数值由战团长在启动会议上签字确认。

### 4.3 波动留痕机制（KP 明确要求）

- 即使未达信息级阈值，但环比波动 >10% 的指标组合，自动写入"波动留痕表"
- **不推送、不打扰**，仅多维表留底
- 作用：避免阈值设得不合理导致漏报；供回溯"这个异常两周前其实有苗头"

## 五、AI 初步归因机制

### 5.1 规则 + LLM 混合归因

**规则负责命中场景**，**LLM 负责把结构化证据转成可读的归因说明**。LLM 不做决策、不输出动作建议给运营。

### 5.2 输入给 LLM 的结构化证据

- 触发的异常类型、等级
- 主指标当前值 vs 近 7/14/30 天均值 vs 基准
- 相关佐证指标偏离情况
- ASIN 基础信息：生命周期、S/A/B 级、所属站点

### 5.3 LLM 输出契约

**① 归因说明**（3–5 句，推送给运营看）：
- 说清"什么指标、偏了多少、可能原因、建议查看哪个模块进一步确认"
- 必须基于证据推理，不得编造数据
- 证据不足时明确说"数据不足，建议检查 XX 模块"，不强行归因
- 结尾必带："*AI 归因仅供参考，请结合实际判断*"

**② 影子 Top3 建议**（不推送，只进影子建议表）：
- 同一次 LLM 调用顺便生成
- 写入多维表隐藏列，对一线运营不可见
- 用途：2 周内积累 ≥50 条带场景的建议，第二阶段与运营实际动作对照打标准确率，达标后再开放直推

### 5.4 对话主动触发的归因

- 运营问 "ASIN xxx 怎么样" → Agent 实时拉数据 → 判定有没有异常 → 有异常给归因说明、没异常给健康总览
- 多轮追问时 Agent 按需补调工具，保持上下文
- 对话只读，第一阶段不支持执行类指令

## 六、飞书触达 + 多维表统一视图

### 6.1 飞书机器人三档卡片

**🔴 紧急卡片（即时推送 @负责人）**
- 红色色条 + "【紧急】"+ 异常类型
- ASIN / 站点 / 负责人 / 链接等级
- 关键指标偏离大字号展示（如"周销量 -42%"）
- AI 归因说明（3–5 句）
- "在多维表查看"按钮 + 领星详情链接
- 同 ASIN 同类型当日不重复推

**🟡 警告卡片（即时推送不加急）**
- 黄色色条 + "【警告】"
- 结构同紧急，视觉弱一档（不大数字、不 @）
- 同 ASIN 同类型当日不重复推

**🔵 信息日报（每日 9:00 一条汇总）**
- 蓝色色条 + "【日报】MM/DD 链接异常概览"
- 汇总统计：扫描 X 个 S/A 链接 / 紧急 Y / 警告 Z / 信息 N
- 按站点/负责人分组 Top 异常列表
- "查看完整多维表"按钮

**对话消息（主动触发）**
- 直接在对话线程用富文本回复
- 支持多轮追问
- 末尾附"在多维表查看"

### 6.2 三张多维表

**表一：异常告警表（主表·核心视图）**

| 字段 | 类型 | 说明 |
|------|------|------|
| 日期 | 日期 | 异常发现日期 |
| ASIN | 文本 | 父ASIN |
| 站点 | 单选 | US/UK/DE... |
| 链接名称 | 文本 | 方便识别 |
| 链接等级 | 单选 | S/A/B |
| 负责人 | 人员 | @对应运营 |
| 异常类型 | 单选 | 销量骤降/断货/差评/ACOS/排名... |
| 异常等级 | 单选 | 紧急/警告/信息 |
| 触发指标 + 偏离度 | 文本 | "周销量 -42%，近 30 天 120 单→本周 70 单" |
| AI 归因说明 | 长文本 | LLM 生成的 3–5 句归因 |
| 影子建议 | 长文本 | 默认隐藏，第二阶段开放 |
| 状态 | 单选 | 待处理/处理中/已处理/误报 |
| 运营备注 | 长文本 | 运营填处理情况 |
| 领星链接 | URL | 跳领星详情 |

视图：
- **"我的待处理"**：按负责人过滤，状态=待处理/处理中
- **"今日紧急"**：今天 + 等级=紧急，红色高亮
- **"按站点"**：按站点分组
- **"本周全量"**：本周所有异常，供站团长/战团长看

**表二：波动留痕表（不推送只留底）**

| 字段 | 说明 |
|------|------|
| 日期 / ASIN / 站点 / 负责人 | 基础信息 |
| 波动指标 + 偏离度 | 例"Sessions -12%，未达警告阈值" |
| AI 简要说明 | 一句话（"流量小幅下滑，建议持续观察"） |
| 是否升级为告警 | 后续如达阈值自动关联 |

**表三：影子建议表（独立权限·第二阶段用）**

- 默认对一线运营隐藏，仅项目组可见
- 每条建议关联异常告警表记录
- 字段：异常ID / 场景 / Top3 建议 / 生成时间 / 后续是否采纳（第二阶段对照运营实际动作打标）
- 用途：2 周积累 ≥50 条，第二阶段评估准确率

### 7.4 成功标准（D14 验收）

1. **链路跑通**：每日 9:00 扫描试点 S/A 级 ASIN → 命中异常 → LLM 归因 → 飞书按等级推送 → 多维表留痕
2. **对话可用**：运营 @机器人问"ASIN xxx 怎么样"，实时拉数返归因
3. **数据真实**：领星真实数据接入，阈值基于会议签字初值
4. **运营开始用**：试点运营每天看推送+多维表，至少标记过 1 次"误报/已处理"
5. **影子建议有积累**：影子建议表 ≥50 条，供第二阶段评估准确率

## 附录：领星 API 接入说明

- **申请入口**：领星 ERP → 设置 → 业务配置 → 全局 → 开放接口 → 输入邮箱进开放后台，自动生成 AppID 和 AppSecret
- **IP 白名单**：同一页面配置出网公网 IP（查询地址 https://toolbox.lingxing.com/api/getIp）
- **API 文档**：https://apidoc.lingxing.com/
- **核心接口模块**：
  - 产品表现（父ASIN/MSKU）：`/erp/sc/routing/data/local_inventory/...`
  - 广告（SP/SD/SB、活动、搜索词）：`/advertising/...`
  - 评论管理：`/review/...`
  - 库存/库龄/FBA：`/inventory/...`、`/fba/...`
  - 竞品监控：`/competitor/...`
- **鉴权**：HTTP Header 携带 AppID + 签名（AppSecret + 时间戳），详见官方签名章节
- **前置依赖**：需企业超管协助开通，是 P0 阻塞项，D1 必须到位
